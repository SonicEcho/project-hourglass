## 目的と完成の基準

ゲーム全体の構想は「ゲーム構想 整理ノート」（`docs/CONCEPT.md`）にある。この試作では戦闘だけを作り、\*\*「この戦闘を何度も遊びたくなるか」\*\*を確かめる。物語、日常パート、育成は作らない。

### 確かめたいこと

- 3人分の行動を、共通の手札5枚と各自の魔法・スキルから割り振る計画の楽しさがあるか（誰に何を使わせるか）
- 手札を使うか残すかの取捨選択と、コンボを狙って組み立てる気持ちよさがあるか
- 弱点を突いてダウン → 追加行動する気持ちよさ、バトンタッチや連携技を狙う工夫が成立するか
- 部位破壊を狙うか早く倒すかの判断が生まれるか
- スマホの縦持ち・片手で、3人分の行動をストレスなく選べるか

（段階6で見直し：はじめは「CTBで行動順を読んで手を選ぶ楽しさ」を確かめる予定だったが、段階5までの試遊で、手札とコンボの組み立てを主役にする方向に変えた。CTB にはこだわらない）

段階7（育成の試作）で、さらに次のことを確かめる。

- 共通の「記憶ポイント」を誰にどう使うか（均等に育てるか、エースを作るか）に悩めるか
- 成長マップで駒を進め、能力値や魔法・スキルが増えていく成長が、目に見えて楽しいか
- 育てた結果（新しい魔法・スキル、上がった能力値）を次の戦闘で実感できるか。戦い方が変わるか
- スマホの縦持ちで、マップを見て次のマスを選ぶ操作がしやすいか

段階8（育成の試作2：ナビカス盤）で、さらに次のことを確かめる。

- 限られたマスに形の違うパーツを詰める「パズル」が楽しいか（コマンドラインの取り合い、バグを避ける並べ方）
- どのパーツを誰の盤にはめるかで、戦い方（ワンモア狙い、バトン役、部位破壊役など）が変わるか
- 成長マップ（量の成長）とナビカス盤（組み合わせの成長）が、役割の違う育成として両立するか
- スマホの縦持ちで、パーツを選んで盤にはめる操作がしやすいか

段階9（育成の試作3：武器ビルドアップ）で、さらに次のことを確かめる。

- 限られた素材（記憶の断片）を、どの武器に吸わせるかに悩めるか
- 進化先の条件を見て「次はあの敵を狩ろう」「このパーツをはめて戦おう」と、戦闘と育成の目標がつながるか
- 進化で戦い方が変わる手応えがあるか（通常攻撃に属性が乗る、盤が広がる）

## 技術構成と開発の流れ

ブラウザで動くWebゲームとして作る。すべてテキストのコードで完結させ、Claude Codeで開発し、スマホのブラウザで確認する。

### 技術構成

| 項目 | 採用するもの | 用途 |
| --- | --- | --- |
| 言語 | TypeScript | 型で壊れにくくする |
| ビルド | Vite | 開発と本番ビルド |
| 描画 | Phaser 3 | 2Dの画面、タップ操作、アニメーション |
| テスト | Vitest | 戦闘ロジックの自動テスト |
| CI・公開 | GitHub Actions → GitHub Pages | pushでテストし、通れば自動公開 |
| スマホ用ログ | eruda（URLに `?debug=1` を付けた時だけ読み込む） | スマホのブラウザでエラーやログを見る |

### 開発の流れ

1. スマホのClaudeアプリから、Claude Codeに作業を頼む
2. Claude CodeがGitHubにpushする
3. GitHub Actionsがテストを実行し、通れば GitHub Pages に公開する。失敗したら公開しない
4. スマホのブラウザで公開URLを開いて確認する（デバッグ時は `?debug=1` を付ける）
5. 不具合や調整点を、また Claude Code に伝える

### フォルダ構成

```
/
├─ src/
│  ├─ core/      戦闘ロジック。Phaserに依存しない純粋なTypeScript
│  ├─ data/      キャラ、カード、スキル、敵の定義
│  ├─ scenes/    Phaserの画面（タイトル、戦闘、結果）
│  ├─ ui/        画面部品（行動順、手札、コマンドなど）
│  └─ debug/     デバッグメニューとログ表示
├─ tests/        core の自動テスト
├─ docs/SPEC.md  この仕様書
└─ .github/workflows/  テストと公開の設定
```

### 設計の原則

- **ロジックと画面を分ける**：`src/core` は Phaser を一切読み込まない。戦闘の状態を受け取り、行動を適用した新しい状態を返す形にして、自動テストで確かめられるようにする
- **データはコードから分ける**：数値の調整がしやすいよう、キャラやカードの数値は `src/data` にまとめる
- **乱数はシード固定できるようにする**：テストやデバッグで同じ結果を再現できるようにする
- **縦持ち 390×844 を基準**に、Phaser の拡大縮小（FIT）で画面サイズに合わせる

## 戦闘ルール

数値はすべて仮。遊んで調整する前提で、`src/data` と定数で変えられるようにする。

### ラウンドの流れ（段階6でCTBから変更）

1. **計画**：ラウンドの始めに、手札を5枚まで補充する。生きている味方全員の行動を1人ずつ選ぶ（選んだら次の仲間へ。仲間をタップすれば選び直せる）。全員選んだら「実行」
2. **実行**：味方と敵の行動を、「行動の速さ」の高い順に1つずつ実行する
3. **ラウンドの終わり**：防御が解ける。次のラウンドへ

- 1人が1ラウンドに行うのは、カード1枚、コンボ1つ、魔法・スキル1つ、基本行動（通常攻撃・防御）のどれか1つ。連携技は2人分の行動を使う
- **行動の速さ = 速さ ÷ 行動の重さ**。重い行動ほど後回しになる。敵の行動の重さは1.0。同じ値なら味方が先、その次は速さの高い順
- 防御は行動の速さに関係なく、ラウンドの最初に効く
- 画面上部に、このラウンドの行動順を表示する。行動を選ぶと、その重さで自分の位置が変わる（予告）
- 単体攻撃の対象が、自分の番が来るまでに倒れていたら、残っている敵に自動で向け直す。回復の対象が倒れていたら何も起きない
- 自分の番が来る前にHPが0になった味方の行動は取り消し。使うはずだったカードは手札に戻る

### 手札とフォルダ

- パーティ共通の山札（フォルダ）20枚を戦闘開始時にシャッフルする
- ラウンドの始めに、手札を5枚まで補充する。使わなかったカードはそのまま残る（取捨選択とコンボ集めのため）
- 計画でカードを割り当てると、そのカードは他の仲間には割り当てられない。実行した時に捨て札へ
- 山札が尽きたら捨て札をシャッフルして山札に戻す
- カードはMP不要。使用者の能力値で効果を計算する

### コンボ

- 手札に決まった組み合わせのカードがそろうと、1人の行動としてまとめて使える大技（材料と効果は「段階5（調整 1回目）」の表）
- 計画で割り当てると、材料のカードはすべてその仲間に割り当てられる

### 魔法・スキルと基本行動

- 魔法・スキルはキャラ固有で、MPを払えばいつでも使える
- 全員共通の基本行動：通常攻撃（物理・威力20・重さ1.0）、防御（このラウンドの間、受けるダメージ半減。ラウンドの最初に効く）

### ダメージ計算

```
ダメージ = 威力 × (物理なら攻撃 / 属性なら魔力) ÷ 対象の防御 × 乱数(0.9〜1.1) × 相性倍率
相性倍率：弱点 1.5 ／ 通常 1.0 ／ 耐性 0.5
回復量 = 威力 × 魔力 ÷ 20
```

- 小数点以下は切り捨て、最低1ダメージ
- 属性は「物理・火・氷・雷」の4種類

### 弱点・ダウン・ワンモア・バトンタッチ

- 弱点を突くと、ダウンしていない敵をダウンさせる
- **割り込み**：ダウンした敵は、次に来る自分の行動を立ち上がりに使い、行動しない。このラウンドまだ動いていない敵をダウンさせれば、その敵はこのラウンド行動できない（速い仲間や軽い行動で先に弱点を突くと、敵の攻撃を止められる）
- **ダウンの歯止め**：立ち上がった敵は、次に自分が行動するまでダウンしない（同じ敵をずっと動けなくすることはできない）
- **ワンモア**：敵をダウンさせた味方は、その場で手札を1枚引いてから、もう1回行動を選べる。まだ誰にも割り当てていない手札のカードやコンボも使える。1回の行動で何体ダウンさせても、ワンモアは1回
- **連鎖ワンモア**：ワンモアやバトンの追加行動で、まだダウンしていない別の敵をダウンさせたら、さらにワンモア。ダウン中の敵はダウンしないので、連鎖は最大で敵の数まで
- **バトンタッチ**：ワンモアの代わりに選べる。指定した仲間（自分以外の生きている仲間）が、その場ですぐに追加の行動を選ぶ。受けた仲間の追加行動はダメージ・回復量が1.25倍。同じ連鎖の中で、渡してきた仲間には渡し返せない
- 追加の行動は、選んだらすぐに実行する（行動の速さは関係ない）。計画していた本来の行動は、そのまま後で行う。その後、ラウンドの残りの行動を続ける
- 見つけた弱点は、敵の上にアイコンで常に表示する（一度突くか、部位破壊で露出すると判明）

### 連携技（試作では1つ）

- 主人公とみおの2人技「クロスドライブ」：敵全体に物理・威力50（耐性を無視）。その後、手札を2枚追加で引く
- 計画で、主人公とみおの2人分の行動を使って選ぶ（2人とも生きていれば、いつでも選べる）
- 行動の速さは、2人のうち遅い方の速さ ÷ 重さ1.5
- ワンモアやバトンの追加行動では使えない

### サポートカード

- ドロー・サーチ・クイックステップの3種類は「サポートカード」。計画の途中でその場で使い、すぐに効果が出る。誰の行動枠も使わない
- 1ラウンドにチーム全体で1枚まで（どれを使うかの選択を残し、連発で山札を掘りすぎないため）
- 計画中に引いたカードは、そのラウンドの行動にそのまま割り当てられる
- 追加行動（ワンモア・バトン）では使えない
- ドロー：手札を2枚引く
- サーチ：山札の上から3枚を見て1枚を手札に加える。残りは山札の一番下へ
- クイックステップ（先制）：仲間1人を選ぶ。その仲間のこのラウンドの行動が、一番最初に実行される（防御の次。先制が複数あれば行動の速さ順）

### 部位破壊

- ボスは本体HPとは別に、部位ごとのHPを持つ
- 部位をタップして攻撃すると、ダメージは部位HPに全額、本体HPに半分入る
- 部位HPが0になると破壊され、その部位を使う行動が封じられたり、隠れた弱点が露出したりする
- 結果画面に、破壊した部位と、手に入るはずの素材（表示のみ）を出す

### 勝敗

- 敵を全滅させると勝利。味方3人のHPがすべて0になると敗北
- HPが0になった味方は行動を選べず、行動順から外れる。試作では蘇生手段なし
- 敗北時は「ボス戦からやり直す」「最初から」を選べる

### 戦闘の構成

1. **戦闘1（雑魚戦）**：スライム、フロストバット、アーマードッグの3体。弱点を突いてワンモアを覚える場

## 画面と操作

縦持ち・片手操作を基本にする。上半分に「読む情報」、親指の届く下半分に「触る操作」を集める。素材は図形と文字の仮のものでよい。

### 画面遷移

タイトル → 戦闘1（雑魚戦）→ 戦闘2（ボス戦）→ 結果画面 → タイトル。敗北時は結果画面から「ボス戦からやり直す」「最初から」を選べる。

### 戦闘画面の5つの領域（上から順に、基準 390×844）

| 領域 | 高さの目安 | 表示するもの |
| --- | --- | --- |

### 操作の流れ（段階6でラウンド制に合わせて変更）

1. 計画：今選んでいる仲間（強調表示）の行動を、手札のカード、コンボ、魔法・スキル、その他から選ぶ
2. 対象（敵、部位、味方）をタップすると、プレビューが出る：予想ダメージ・回復量、弱点に当たるか、行動順での自分の位置

### 盤の基本

- 仲間ごとに盤を1枚持つ。盤はマス目で、キャラごとに形が違う
- 盤の中の1行が「コマンドライン」（盤の上で光る横の帯）
- パーツは色付きのブロック形状（1〜4マス）。盤のマスに、はみ出さず・重ならずに置ける。90度ずつ回転できる
- パーツは2種類
  - **能力値パーツ**：盤のどこに置いても効く
  - **効果パーツ**：コマンドラインに1マス以上乗っている時だけ効く（乗っていなければ何も起きない）

- パーツの色は4色（赤・青・緑・黄）
- 盤の編集は戦闘の外（成長マップの画面から開く）でいつでもできる。何度でも外して付け直せる（費用なし）

## 育成の試作3（段階9：武器ビルドアップ）

構想ノートの「武器ビルドアップ」を、今の周回とナビカス盤につなげて試す。成長マップが「量の成長」、ナビカス盤が「詰めて組み合わせる成長」なら、武器は「育てて分岐する成長」。数値・名前はすべて仮。

### 武器の基本

- 仲間1人に武器1本（持ち替えはしない）。最初の武器：主人公「記録の剣」、あかり「祈りの杖」、みお「投げカード」
- 武器のパラメータ：**攻撃値**（キャラの攻撃に足す）と、**属性値**（火・氷・雷。1につき、その属性のダメージ +2%）
- **記憶の断片**（素材。パーティ共通の持ち物）を武器に吸わせると、パラメータが上がる。吸わせた断片はなくなる。取り消しはできない

- **進化**：武器が Lv3 になり、進化先の条件を満たしていれば、武器の画面で進化できる（1回だけ。進化先は1つ選ぶ。戻せない）。進化すると、パラメータは引き継いだまま、進化先の効果が加わる

| 武器 | 進化先 | 条件（Lv3 に加えて） | 効果 |

| 記録の剣 | フレイムブレード | 火 6 以上 | 通常攻撃が火になる。攻撃 +3 |
| 記録の剣 | ブレイクエッジ | 攻撃値 4 以上、傾向が赤 | 部位へのダメージ +30%。攻撃 +4 |
| 記録の剣 | フロストブレード | 氷 6 以上 | 通常攻撃が氷になる。攻撃 +3 |
| 祈りの杖 | アイスロッド | 氷 6 以上 | 通常攻撃が氷になる（魔力で計算）。魔力 +3 |
| 祈りの杖 | 癒しの杖 | 傾向が緑 | ラウンドの始めに最大HPの5%回復。MP +10 |
| 祈りの杖 | フレイムロッド | 火 6 以上 | 通常攻撃が火になる（魔力で計算）。魔力 +3 |
| 投げカード | サンダーカード | 雷 6 以上 | 通常攻撃が雷になる（魔力で計算）。速さ +2 |
| 投げカード | トリックカード | 傾向が黄 | ワンモアの時に引く枚数 +1。速さ +1 |
| 投げカード | フレイムカード | 火 6 以上 | 通常攻撃が火になる（魔力で計算）。速さ +1 |

- 進化すると、そのキャラの**ナビカス盤に拡張マスが2つ増える**（コマンドラインの行の右端に2マス。構想ノートの「武器が進化すると盤に拡張マス」）。コマンドラインが長くなるので、効果パーツを乗せやすくなる
- 「通常攻撃が○になる」は、通常攻撃で弱点を突けるようになる（ワンモアの手段が増える）。属性の通常攻撃は、物理ではなく魔力で計算する
- 進化先の効果のうち、部位ダメージ・回復・ワンモアの枚数は、ナビカス盤と同じ「キャラの特性」として戦闘に渡す

### パーツの傾向（構想ノートの「隠しパラメータ」）

- 戦闘に勝つたびに、そのキャラの盤にはまっているパーツの色ごとのマス数を、その武器に貯める
- 「傾向が赤」＝貯まった中で赤が一番多い（同じ数なら傾向なし）
- 構想ノートでは隠しパラメータだが、試作では武器の画面に「いちばん多い色」として見せる（条件に使うので、見えないと狙えないため）

### 画面（縦持ち 390×844）

- 成長マップの画面の下のボタンを2つに分ける：「ナビカス盤」と「武器」
- 武器の画面：上から、キャラの切り替え（主・あ・み）、武器のカード（名前、Lv と経験値のバー、攻撃値・火・氷・雷、傾向）、進化先の3つ（条件を1つずつ ✓／✗ で表示。全部 ✓ なら「進化」ボタン）、持っている断片の一覧（タップで選び、「吸わせる」で決定）、「成長マップへ戻る」
- 戦闘に勝った時、手に入れた断片と、武器の経験値・レベルアップを勝利の表示に出す
- 進化した時は、短い演出（武器の名前が光って変わる）を入れる

### 戦闘への反映

- 戦闘に使うキャラは、成長マップ → ナビカス盤 → 武器の順に反映する
- 武器の攻撃値はキャラの攻撃に、進化先の能力値はキャラの能力値に足す。属性値の割増しと進化先の効果は「キャラの特性」として渡す
- 通常攻撃の属性は、キャラの定義に持たせて、戦闘ロジックが読む

### 数値の調整

- 武器の分だけパーティが強くなるので、段階8と同じ自動対戦で勝率を測り、ボスの数値を調整し直す（目安はこれまでと同じ：ボスに1回目で勝てる割合が約3割）。自動対戦では、断片をでたらめな武器に吸わせ、進化できる時は最初の進化先を選ぶ

### 段階9（調整1回目）：素材と断片化

敵が「記憶の断片」を直接落とすのをやめる。敵が落とすのは**素材**で、勝利の報酬で**通常アイテム**も手に入る。素材やアイテムを**断片化**すると断片になり、それを武器に吸わせる。上の「記憶の断片（素材）」の内容は、この節で置き換える。数値・名前はすべて仮。

**流れ**

敵を倒す → 素材が手に入る（勝利の報酬で通常アイテムも1つ）→ 武器の画面で素材・アイテムを選んで「断片化」→ 断片になる → 断片を武器に「吸わせる」

- 素材と通常アイテムは、パーティ共通の持ち物。断片化すると素材・アイテムはなくなる（戻せない）
- 通常アイテムは、この試作では戦闘で使えない（断片化の元にするだけ）
- 断片は、元の素材・アイテムごとに特徴が違う（「スライムゼリーの断片」「エーテルの断片」のように、元の名前で呼ぶ）。1つの素材から断片が2つ出るものもあり、別々の武器に分けて吸わせられる

**素材（敵が1つずつ落とす）**

| 素材 | 落とす敵 | 断片化すると | 断片1つの効果 |
| --- | --- | --- | --- |
| スライムゼリー | スライム | 1つ | 火 +3、攻撃 +1 |
| 霜の羽 | フロストバット | 1つ | 雷 +3、氷 +1 |
| 硬い毛皮 | アーマードッグ | 1つ | 氷 +3、攻撃 +2 |
| 鋼の爪 | 戦闘4の強化版の敵（上の素材に加えて落とす） | 1つ | 攻撃 +3 |
| 歪んだ腕殻・歪みの角片 | ボスの部位（結果画面に表示するだけ。今と同じ） | ― | ― |

**通常アイテム（戦闘に勝つと1つ。戦闘ごとに決まっている）**

| アイテム | 手に入る戦闘 | 断片化すると | 断片1つの効果 |
| --- | --- | --- | --- |
| ポーション | 戦闘1、戦闘3 | 2つ | 攻撃 +1 |
| エーテル | 戦闘2 | 2つ | 火 +1、氷 +1、雷 +1 |
| ハイポーション | 戦闘4 | 2つ | 攻撃 +2 |

- 戦闘3までに手に入るもの：スライムゼリー4、霜の羽2、硬い毛皮1、ポーション2、エーテル1。断片にすると 火12・雷6・氷6〜7 ほど（今の「赤4・黄2・青1」とだいたい同じ量で、組み合わせ方の幅が広がる）
- 進化の条件（火・氷・雷 6以上など）と経験値は、今のまま

**画面**

- 武器の画面の下の段を「素材・アイテム」と「断片」の2つのタブに分ける
  - 素材・アイテム：持っている数と「断片化すると何になるか」を出す。選んで「断片化」
  - 断片：今と同じ。選んで「吸わせる」
- 戦闘に勝った時の表示は「素材：スライムゼリー×2　アイテム：ポーション」のようにする
- デバッグメニューの「断片を全種類2つずつもらう」は「素材とアイテムを全種類2つずつもらう」に変える

**ロジック**

- 戦闘の結果（`getBattleResult`）の `drops` は素材の id にする（敵の `drops` を素材に置き換える）。通常アイテムは周回の構成（`CAMPAIGN`）に戦闘ごとに持たせる
- 持ち物（`ArmoryState`）に「素材・アイテム」と「断片」を分けて持つ。断片化（`fragmentItem`）は、素材・アイテムを1つ減らし、決まった断片を決まった数だけ増やす

## セーブと中断・再開（段階11）

`docs/ROADMAP.md` の M0（本格開発の土台）の最初の作業。遊びの中身は変えず、途中で閉じても続きから遊べるようにする。M0 の「用語と名前を決める」は段階10でおおむね済んだ（敵・技などの固有の名前は、決まってから置き換える）ので、次の「セーブ・ロード」から始める。

**範囲**

- 戦闘の外（星図・ムーブメント・武器の画面）で閉じても、続きから遊べる。戦闘の途中で閉じた時は、その戦闘の前（星図）から再開する。戦闘中のセーブは M2 で作る
- セーブは1つだけ（自動のセーブ）。自分で選ぶセーブの枠は作らない

**保存するもの**：今の周回の状態（`run`）

| 中身 | 内容 |
| --- | --- |
| 版の番号 | セーブの形の版（今は1）。形を変えたら番号を上げ、古い版から新しい版に直す手順（移行）を足す |
| 保存した日時 | タイトルの「つづきから」に出す |
| 乱数のシード | 次の戦闘の並びを、閉じる前と同じにする（固定中かどうかも） |
| 次の戦闘の番号 | 何戦目の前か |
| 星図 | 星の砂、キャラごとに開けたマス |
| ムーブメント | 持っているギアと、どの盤のどこにはめたか |
| まだ受け取っていない報酬 | ギアの候補（受け取る前に閉じても、星図に戻ると選べる） |
| 武器 | 3人の武器（パラメータ、経験値、傾向、進化先）、素材・アイテム、記憶の欠片 |

**いつ保存するか（自動）**

- 星図の画面に入った時（戦闘に勝って戻った時を含む）
- 星図・ムーブメント・武器の画面で何かを変えた時（マスを開ける、ギアをはめる・外す、報酬を受け取る、時分解、吸わせる、進化）
- 戦闘に勝って星の砂などを受け取った時（「星図へ」を押す前に閉じても消えないように）
- ブラウザが裏に回った時（アプリの切り替え、タブを閉じる）。戦闘中なら、その戦闘の前の状態を保存する
- 最後のボスに勝って周回を終えたら、セーブを消す

**タイトル画面**

- セーブがある時は「つづきから」を大きく出し、その下に「何戦目の前か」と保存した日時を小さく出す。押すと星図から再開する
- その下に「はじめから」。セーブがある時は、1回目に押すと「セーブを消して最初から始めます。もう一度押してください」と出し、2回目で始める（誤タップで消さないように）
- セーブが壊れていて読めない時は「セーブを読めませんでした」と出し、「はじめから」だけにする。壊れたセーブは消さずに別の場所に残す（原因を調べられるように）
- URL の `?seed=数字` がある時は、つづきからでも URL のシードを優先する

**データの形が変わっても読めるように**

- 版の番号が古いセーブは、移行の手順を順に通して今の版に直してから読む。今の版より新しい（知らない）版は読まない
- 読む時に、今のデータにない名前（星図のマス、ギア、素材・アイテム、記憶の欠片、武器、進化先）は捨てる。キャラや武器が足りなければ、初めの状態で補う。ギアは、はめた順に今の盤に置き直し、置けないものは外す（盤の形が変わっても壊れない）
- 次の戦闘の番号は、今の周回の範囲に収める

**保存する場所を差し替えられる形**

- 保存の窓口（読む・書く・消す）を1か所にまとめ、今はブラウザの保存（localStorage）を使う。アプリにする時は、この窓口の中身だけを差し替える
- セーブの中身を作る・読む・直す処理は `src/core/save.ts`（Phaser もブラウザの保存も使わない）に置き、テストする
- 保存できない時（容量がいっぱい、プライベートモードなど）は、遊びは止めずに、コンソールにエラーを出す

**デバッグメニュー**（`?debug=1`）

- 「セーブの中身を見る」：版の番号、保存した日時、大きさ（文字数）、中身（JSON）を出す
- 「セーブを消す」

## 自動対戦の測定をスクリプトに（段階12）

M0 の2つ目の作業。これまで数値を決める時に、その場で書いて回していた「自動対戦で勝率を測る」やり方を、いつでも同じ条件で回せる道具にする。遊びの中身と数値は変えない。

**測るもの**：タイトルから5戦目のボスまでの周回を、決まった方針で自動で遊ぶ（これまでの測り方と同じ）

| 場面 | 自動の方針 |
| --- | --- |
| 戦闘 | 手をほぼでたらめに選ぶ（今の `tests/core/simulation.test.ts` の `autoPlay` と同じ。候補の先頭5つからでたらめに。サポートは半分の確率で使う。追加行動は3回に1回バトンタッチ） |
| 星図 | 星の砂を、でたらめなキャラの、開けられるでたらめなマスに、払えなくなるまで使う |
| ギアの報酬 | 候補の先頭から選ぶ |
| ムーブメント | 大きいギアから順に、効果ギアはブリッジに乗る場所を優先し、狂い（同じ色が隣）を作らない場所にはめる。キャラは順番に回す |
| 武器 | 素材・アイテムはすべて時分解し、記憶の欠片をでたらめな武器に吸わせる。進化できる時は最初の進化先を選ぶ |
| 負けた時 | 育成はそのまま、同じ戦闘を別のシードでやり直す（最大20回） |

**出す結果**（戦闘ごとの表）

- 1回目で勝てた割合（これまでの目安：戦闘1・2 は100%、戦闘3 約9割、戦闘4 約6〜8割、ボス 約3割）
- 勝った時の平均ラウンド数、平均のやり直し回数
- 最後まで勝ち切れた周回の割合と、測った回数・シード

**使い方**

- 開発環境：`npm run measure`（回数とシードは `npm run measure -- --runs 300 --seed 1` のように変えられる）。同じ回数・シードなら同じ結果になる
- スマホから：GitHub の Actions の「Measure」を手で実行すると（回数を指定できる）、結果の表が実行結果のページ（Summary）に出る。`main` に push した時にも自動で回る。測定は公開の処理とは別なので、測定が遅くても公開は待たない
- 自動の方針は `src/sim/`（Phaser を使わない）に置き、テストは周回が最後まで進むこと・同じシードで同じ結果になることを確かめる。今の `tests/core/simulation.test.ts` は、`src/sim/` の自動の戦闘を使う形に直す

### 段階2（戦闘ロジック）

**仕組み**

- `src/core` の公開関数は、戦闘の状態を受け取って新しい状態を返す（元の状態は変えない）。主なもの：`createBattle`、`startNextTurn`、`runEnemyTurn`、`advanceToPlayerTurn`（敵の手番を進めて味方の手番まで進める）、`getActionError`（行動できない理由）、`applyAction`、`previewAction`、`getTurnForecast`、`canUseLink`、`batonTargets`、`getBattleResult`
- 戦闘の出来事はすべて `state.log` に構造化して残す（行動、ダメージ、CTの変化、ダウン、ワンモア、部位破壊など）。画面の演出とデバッグの戦闘ログはこれを使う
- 乱数は mulberry32。シードは `createBattle` に渡し、乱数の内部状態も戦闘の状態に持つ
- 戦闘の構成は `src/data/encounters.ts` の `createEncounterSetup('battle1' | 'battle2', seed)` で作る。毎戦闘、HPとMPは全回復した状態で始まる

**行動順（CTB）**

- CTは「次に行動する時刻」の累計値として持つ。行動すると待ち時間が加算され、最も小さい者が次に行動する
- 戦闘開始時のCTは、重さ1.0の行動をした時と同じ `ceil(100 ÷ 速さ)`
- CT・陣営・速さがすべて同じなら、並び順（味方 → 敵の登録順）
- 行動順の予測では、まだ決まっていない行動は重さ1.0とみなす。ダウン中の敵の立ち上がりも重さ1.0
- 敵の行動の重さはすべて1.0

**ダメージと回復**

- ボスの「歪みの咆哮」の「魔法」は、属性を持たない魔法とする。魔力で計算し、相性（弱点・耐性）の影響を受けない
- 回復に乱数はない。最大HPを超えない。HPが0の味方は回復できない
- 倍率（相性、バトン1.25倍、防御0.5倍）はすべて掛けてから最後に切り捨てる

**ワンモア・バトンタッチ**

- 弱点を突いて倒した敵はダウンしない。ワンモアにもならない
- バトンを受け取った仲間は、通常の手番と同じに扱う。手札を補充し、防御を解き、行動すると待ち時間を加算する。その手番でもワンモアできる
- バトンを渡してきた仲間には、渡し返せない（同じ流れの中で）
- バトンの1.25倍は、受け取った仲間の次の1回の行動で使い切る（ダメージや回復でない行動でも消える）

**連携技**

- 「手番が敵を挟まずに連続している」の判定：今の手番が主人公かみおで、行動順の表示（8手番）で、もう一方の次の手番までに敵の手番がないこと。あかりの手番が間に挟まるのはよい
- ワンモア中は使えない（両者の待ち時間を加算するルールと合わないため）
- ダメージは2人の攻撃の平均で計算する。発動した側がバトンを受けていれば1.25倍が乗る

**手札**

- 手札の上限はない。補充は5枚までだが、ドローやクロスドライブで5枚を超えてもよい
- 使ったカードは効果の前に捨て札へ移す
- 山札も捨て札も空なら、引ける分だけ引く
- すりかえは、捨て札が空だと使えない

**部位破壊**

- 単体攻撃（通常攻撃を含む）はすべて部位を狙える。全体攻撃は本体だけに当たる
- 部位を狙った時：部位には「ダメージ × 部位倍率（ブレイク系は2）」、本体には「ダメージ × 0.5」（切り捨て、最低1）。相性は本体のものを使う
- 壊れた部位は狙えない
- 素材の名前（仮）：右腕「歪んだ腕殻」、角「歪みの角片」

**ボスの行動**

- 「HPが半分を切ったら、2回に1回は全体攻撃」は、半分を切ってからの1回目、3回目、5回目…の行動を、使える全体攻撃から選ぶこととする。それ以外は使える行動からランダム

**プレビュー**

- まだ判明していない弱点は、通常の相性として計算する（プレビューで弱点が分かってしまわないように）。耐性はそのまま反映する

### 段階3（戦闘画面）

- 戦闘画面の5つの領域に加えて、次の2つを置く

- 対象を選ぶ行動は、同じ対象をもう一度タップするか、「実行」で決定する
- 選び直し：別のカード・スキル・対象をタップすると切り替わる。何もない所をタップするか、選んでいるカードをもう一度タップすると取り消す
- 行動順の予告：行動を選ぶと、その行動の重さで行動順を並べ直し、自分の次の手番のアイコンを黄色の枠と「次」で示す
- バトンタッチを選ぶと、渡せる仲間に黄色の枠が付く
- 演出：行動名の帯 → ダメージ・回復の数値、WEAK!、耐性、DOWN、ONE MORE!、BATON TOUCH!、撃破。演出中は画面のどこをタップしても早送りになる
- 長押しの詳細は画面中央に出し、タップで閉じる
- 高解像度のスマホで文字がにじまないよう、内部では端末の画素密度（最大3倍）で描く。座標は 390×844 のまま
- 段階3では、戦闘1だけを遊べる。勝敗がついたら「勝利！／敗北…」と「もう一度」（戦闘1を新しいシードでやり直す）を出す。タイトル、ボス戦、結果画面は段階4で作る（段階4で置き換え済み）

- 戦闘の出来事は `[battle]` 付きでコンソールに出す（`?debug=1` の eruda で見られる）
- 予想ダメージでは、まだ判明していない弱点は通常として計算するが、耐性はそのまま反映する（段階2の決定どおり）

**画面遷移**

- タイトル（「はじめる」）→ 戦闘1 → ボス戦 → 結果画面 → タイトル
- 戦闘1に勝つと「勝利！ 次はボス戦（HPとMPは全回復する）」と「ボス戦へ」ボタンを出す

- 結果画面：勝利なら「クリア！」と「タイトルへ」。敗北なら「ボス戦からやり直す」（ボス戦で負けた時だけ）、「最初から」（戦闘1から）、「タイトルへ」
- 結果画面には、勝敗にかかわらず、破壊した部位と手に入るはずの素材（表示のみ）を出す

**乱数のシード**

- 1回の通しプレイでシードを1つ持つ。戦闘1はそのシード、ボス戦はシード+1を使う
- 「はじめる」「最初から」「ボス戦からやり直す」のたびに新しいシードにする。ただし `?seed=数字` やデバッグメニューで固定している時は変えない（同じ展開を再現できる）

**ボスと部位**

- 部位を持つ敵が1体だけの時（ボス）は、本体を大きく描き、その下に部位ごとのパネル（名前、部位HP、HPバー）を並べる
- 本体をタップすると本体を、部位のパネルをタップすると部位を狙う。壊れた部位は「破壊」と出て狙えない
- 部位を狙った時のプレビューは「部位のダメージ／本体のダメージ」を出す
- 演出：部位のダメージ数値（橙色）、「部位破壊！」、部位破壊で弱点が露出した時は「弱点露出：雷」
- 部位を長押しすると、部位HP、破壊で封じられる行動、手に入る素材を出す。隠れた弱点は書かない（壊してからのお楽しみ）

**デバッグメニュー（`?debug=1` の時だけ）**

- 画面左下の小さな「DBG」ボタンから開く。Phaser の外の HTML で作り、長いログもスクロールして読めるようにした
- 項目：味方を全回復する（HPが0の味方も戻る）／敵ごとの「HPを1にする」（生きている敵だけ）／戦闘1を飛ばしてボス戦から始める／シードの表示・固定・指定して最初から／戦闘ログの一覧

### 段階5（調整 1回目）

遊んだ感想「連携技の説明が見られない」「連携技にもっと特別感がほしい」「カード（デッキやドロー）の良さが薄い」「ロックマンエグゼのプログラムアドバンスのように、手札の組み合わせでコンボを出したい」「重さの数値の見方がわからない」をもとに調整した。

**コンボ（新しいルール）**

- 手札に決まった組み合わせのカードがそろうと、まとめて使える大技。1回の行動として扱い、使うと材料のカードはすべて捨て札へ
- カードと同じくMP不要。使用者の能力値で計算し、バトンの1.25倍も乗る
- ドロー・すりかえ・シャッフルで材料を集める、という手札作りの楽しみを作るのがねらい
- 定義は `src/data/combos.ts`

| コンボ | 材料 | 効果 | 重さ |
| --- | --- | --- | --- |
| エレメントバースト | ファイアチップ＋アイスチップ＋サンダーチップ | 敵全体に威力40。敵ごとに火・氷・雷から一番効く属性（弱点があれば弱点、なければ耐性でない属性）を自動で選ぶ | 1.5 |
| トリプルソード | ソード×3 | 敵単体に物理・威力35を3回。耐性を無視 | 1.5 |
| ブレイククラッシュ | ブレイクアーム×2 | 敵単体に物理・威力50。部位へのダメージ3倍 | 1.3 |
| ヒールサークル | リカバー×2 | 味方全体を回復・威力45 | 1.0 |

- 連続攻撃の途中で敵が倒れたら、残りの攻撃は当たらない。途中で部位が壊れたら、残りは本体に当たる
- エレメントバーストのプレビューでは、まだ判明していない弱点は使わずに予想する

**連携技**

- クロスドライブは耐性を無視する（物理に耐性のあるスライム・アーマードッグにも全力で当たる）
- 使う時に専用のカットイン（2人の名前の帯が左右から入り、技名を大きく出す → 白く光る）を入れ、ダメージの数値を大きくして画面を揺らす
- 「連携技」ボタンは、光っていなくても長押しで説明（効果、使える条件、使った時の待ち時間）を見られる。光っている時はボタンに技名も出す
- 使える時は、行動順で今の行動者と相方のアイコンを金色の線でつなぐ

**カード**

- ソードの威力を30→35、属性チップ3種の威力を35→40に上げた（同じ属性の魔法と同じ威力で、MPがいらない）

**重さの見せ方**

- 数値の代わりに「軽い（0.6以下）／普通（1.0以下）／重い（1.3以下）／超重い（それより上）」と4段階の目盛りで出す。区切りは `src/data/constants.ts` の `WEIGHT_LABELS`
- カード・スキル・コンボを長押しすると、「重さは行動してから次の手番が来るまでの長さ。重いほど次の手番が遅い」という説明と、今の行動者が使った時の待ち時間を出す

**画面**

- 手札の上に「コンボの帯」を置く。使えるコンボは金色（★）でタップすると選べる。あと1枚でそろうコンボは「あと1枚」と出す。帯を長押しするとコンボの一覧（材料、効果、今そろっている枚数）を出す
- 使えるコンボの材料になっている手札のカードには、金色の「C」の印を付ける。コンボを選ぶと材料のカードが赤枠になる
- コンボを使う時は「COMBO!」の帯のカットインを入れる
- 連続攻撃の予想ダメージは、同じ対象への分を足し合わせて出す

### 段階5（調整 2回目）：手札の入れ替え

感想「カードを使ったら次の手番では手札を捨てて新しい手札にすることで、取捨選択の要素を入れたい」をもとに、手札のルールを変えた。

- 「手番の流れ」でカード（コンボ含む）を1枚でも使ったら、次の味方の手番の始めに、手札をすべて捨て札へ送り、新しく5枚引く
  - 手番の流れ＝味方の手番の始めから、ワンモアやバトンタッチで続く間。この間は同じ手札を使い続けられる（弱点を突けば手札を2枚使える）
  - バトンを受けた仲間の手番は流れの続きなので、手札の入れ替えも引き足しもしない
- カードを使わなかった（魔法・スキル、通常攻撃、防御、連携技だけの）流れの後は、手札を残して1枚引く。上限は7枚（`HAND_MAX`）。手札を残してコンボの材料がそろうのを待つ、という選択ができる
- ドローは使っても手札を入れ替えない（引いたカードを次の手番に持ち越せる）。カードの定義の `keepsHand` で決める
- クイックステップは入れ替えの対象（何もせず素早く手札を入れ替える手段になる）
- 画面：手札の上の行の右に「次の手番：手札を入れ替え」または「次の手番：手札を残して+1枚（最大7）」を出す。長押しで手札のルールの説明。手番の始めの文字に「手札を入れ替えた」「手札を残して+1枚」を添える。カードの長押しにも、使うと手札が入れ替わるかを書く

### 段階6（ラウンド制への作り直し）

**ロジック（`src/core`）**

- 主な関数：`createBattle`（1ラウンド目の計画の状態で始まる）、`setPlan`／`clearPlan`／`getPlanError`（計画）、`useSupport`／`resolveSearch`（サポートカード）、`startExecution`／`step`／`runUntilInput`（実行）、`applyExtra`／`passBaton`／`declineExtra`（追加行動）、`getRoundOrder`（行動順と予告）、`previewAction`
- 戦闘の局面（`phase`）は plan（計画）／execute（実行）／extra（追加行動を選ぶ）／ended（勝敗がついた）
- 計画で割り当てたカードは「確保」され、実行するまで手札に残る。自分の番の前に倒れたら、確保していたカードはそのまま手札に残る
- 追加行動は「見送る」こともできる
- 待ち時間（CT）の仕組みと、段階5で入れた「カードを使ったら手札を入れ替える」ルールは取り除いた
- 新しい数値：`DEFAULT_ACTION_WEIGHT`（予告で未定の行動に使う重さ 1.0）、`ONE_MORE_DRAW`（ワンモアで引く枚数 1）、`SUPPORT_PER_ROUND`（1ラウンドのサポートカード 1枚）

**画面**

- 行動順の帯は「このラウンドの順番」。左上に R（ラウンド数）。まだ行動を決めていない仲間は薄い色と「?」、防御は「防」、先制は「先」、行動を選んでいる時の自分の予告位置は黄色い枠と「ここ」。連携技は「主み」のように1つにまとめる
- 計画中は、行動を選んでいる仲間の枠を白く強調する。決めると、まだ決めていない次の仲間に自動で移る。仲間の枠をタップすると、その仲間の行動を選び直せる
- 仲間の枠に、決めた行動を「▶ソード→スライム」のように出す（長い時は「…」で切る）
- 手札：他の仲間が確保しているカードは暗くして「○○が使う」と出す。サポートカードは「行動枠なし」。手札の上の行に「サポート：あと1枚使える／このラウンドは使用済み」
- 下のボタン：行動を選んでいる最中は「キャンセル／決定」、それ以外は「実行」（全員の行動が決まると押せる）
- 追加行動中は、「その他」に「追加行動を見送る」を出す
- 実行中は1つずつ演出する（タップで早送り）。ラウンドの切り替わりに「ラウンド N」の帯を出す
- デバッグメニューの戦闘ログは、ラウンドの区切りと追加行動（★）が分かるようにした

**遊んで確かめたいこと（調整の候補）**

- ラウンド制では敵が毎ラウンド必ず動くので、敵の攻撃が1人に集中した時の被害が大きい（試遊で、1ラウンドに主人公が3回狙われて倒れることがあった）。敵の攻撃力や、仲間のHPの調整が必要かもしれない

### 段階5（調整 3回目）：ボスの強さと大技の予告

感想「ボスの攻撃が強すぎて即死する。攻略法はあるのか」をもとに調整した。ラウンド制ではボスが毎ラウンド必ず動くため、全体攻撃2回でみお・あかりが倒れ、回復が追いつかず、攻略の流れ（角を壊す → 雷で割り込み）が成立していなかった（自動対戦で勝率0%）。

**大技の予告（ため）**

- 敵の行動に「大技」（`charge`）を足した。大技を選んだ敵は、まず「力をためる」（そのラウンドは攻撃しない）。次の自分の行動で、ためた大技を放つ
- ためている間は、敵の上に「ため：薙ぎ払い（全体）」、行動順のアイコンに「大技」、計画中の案内に「⚠ ○○の構え！」を出す
- 止め方：ダウンさせると、ためが解ける（割り込みと合わせて大技が不発になる）。ためている大技を使う部位を壊すと、その場でためが解ける。防御でしのぐこともできる
- 部位破壊で解けるのは、その部位を使う大技だけ（歪みの咆哮＝角）。薙ぎ払いはどの部位も使わないので、ダウンさせるか防御でしのぐしかない
- 予告の案内とボスの詳細には、その時に本当に使える止め方だけを出す（例：「止め方：角を壊す／防御でしのぐ」。ダウンは弱点が分かっている時だけ書く）。はじめは一律に「ダウン・部位破壊で止めよう」と出していて、薙ぎ払いでも部位破壊で止まると誤解させていた
- ボスの薙ぎ払い・歪みの咆哮を大技にした。叩きつけ（単体）はためずにすぐ使う
- 使える行動が1つも残っていない敵は何もしない

**数値**

- 仲間のHPを1.2倍：主人公 144、あかり 120、みお 102
- ボス：HP 750、攻撃 18、魔力 15。薙ぎ払い 威力28、歪みの咆哮 威力32、叩きつけ 威力40
- 目安（自動対戦：手をほぼでたらめに選ぶ）：雑魚戦の勝率 約7割、ボス戦の勝率 約3割（平均9ラウンド前後）。考えて防御や割り込みを使えば、もっと勝てる想定
- ボスの攻撃1回のダメージの目安：全体攻撃で 主人公 36〜46、あかり 43〜55、みお 54〜69。叩きつけはみおに 81〜99（HP102なので一撃では倒れない）

### 段階9（調整1回目）：素材と断片化

- 素材・通常アイテムは `ItemDef`（`src/data/weapons.ts` の `ITEMS`）。断片は元の素材・アイテムごとに1種類（`FRAGMENTS`。id は元の素材・アイテムと同じ）

- 自動対戦（素材・アイテムはすべて断片化し、でたらめな武器に吸わせる）で、戦闘3は約95%、戦闘4は約78%、ボスは約32%。アイテムの攻撃値の分だけ戦闘4が少し楽になったが、ボスは目安どおりなので数値は変えていない

### 段階10（名前の置き換え）

- タイトル画面は「RESTOPIA」とキャッチコピー「思い出だけの理想郷」、その下に「バトルプロトタイプ」。ブラウザのタブの題名も「RESTOPIA - Battle Prototype」にした
- まだ古いままの名前：ボス「歪みの獣」と部位の素材（歪んだ腕殻・歪みの角片）、敵（スライムなど）、技（ファイア・ファイラなど）、スナップの名前（〇〇チップなど）、アイテム（ポーションなど）、武器（記録の剣など）、ギアの名前（〇〇メモリなど）。名前を決めてから置き換える
- 不具合の修正：星図で技を覚えて4つ以上になると、戦闘の「魔法・スキル」の一覧の4つ目以降が下のコマンドのボタンに隠れて押せなかった（一覧を手札の場所に1列で並べていて、3つまでしか収まらなかった）。3つまでは今までどおり1列、4つ以上は2列（技の名前と「MP・属性・重さ」の2行）にして、1ページに6つまで並べる。6つを超える時は、1ページに5つと「次のページ」のボタンを並べ、押すとページが進む（最後のページの次は最初に戻る）。並べ方は `src/ui/skillLayout.ts`、テストは `tests/skillLayout.test.ts`

### 段階11（セーブと中断・再開）

- セーブの中身を作る・読む・直す・整える処理は `src/core/save.ts`（`serializeSave`・`parseSave`・`sanitizeRun`、版の番号 `SAVE_VERSION`、移行の手順 `MIGRATIONS`）。テストは `tests/core/save.test.ts`
- 保存の窓口は `src/save/storage.ts`（`SaveStorage`：読む・書く・消す）。今は localStorage。周回の状態との橋渡し（`saveRun`・`continueRun`・`finishRun` など）は `src/scenes/run.ts`
- 保存の場所の名前：自動のセーブは `restopia.save.auto`、読めなかったセーブの退避先は `restopia.save.broken`（退避先は1つだけで、次に壊れたら上書き）
- 星図・ムーブメント・武器の画面は、何かを変えるたびに描き直す（`render()`）ので、そこで保存する。日時を除いた中身が前と同じなら書き込まない（項目を選んだだけの描き直しでは書き込まない）
- `run.active`：周回を始めた・続けた時に true、ボスに勝ったら false。false の間（最初のタイトル、クリア後）は保存しない。負けて「タイトルへ」戻った時は、その戦闘の前のセーブが残り、「つづきから」で星図から再開する
- 「この戦闘からやり直す」で変えたシードは、次に星図に入るか裏に回った時に保存される
- 読む時に整える：0個になった素材・アイテムや欠片は捨てる。開けたマスは、出発点を先頭にして残す（開けた順を保つ）。同じ番号（uid）のギアが2つあれば後のものを捨て、次の番号は持っているギアの番号より大きくする。ギアは武器の進化で広がった盤（`naviDataWithWeapons`）に置き直す（武器を先に整える）。進化先が今のデータにない武器は進化前に戻す
- タイトルの「つづきから」の下には「戦闘1の前（1/5）　10/7 21:05」のように出す（日時はスマホの時刻）
- デバッグメニューの「セーブを消す」は、確認のダイアログを出してから消し、次に「はじめる」まで自動のセーブも止める（すぐ書き直されないように）

### 段階12（自動対戦の測定をスクリプトに）

- 自動の戦闘は `src/sim/autoBattle.ts`（`autoPlay`、`lcg`。`tests/core/simulation.test.ts` にあったものを移した。中身は変えていない）、周回は `src/sim/autoRun.ts`（`autoRun`、`arrangeNavi`）、集計と表は `src/sim/measure.ts`（`measure`、`summarize`、`formatMeasure`）。テストは `tests/sim.test.ts`
- `npm run measure` は `scripts/measure.mjs`。TypeScript のまま読み込むため、Vite の `runnerImport` を使う（道具を増やさない）。既定は200周・シード1。200周で約20秒
- シード：周回 k 回目のシードは「最初のシード＋k×10000」。戦闘のシードは画面と同じ「周回のシード＋戦闘の番号」で、やり直すたびに +100 する（周回どうしで重ならないように離した）
- ボスに勝った戦闘は、報酬を受け取らない（周回の終わりなので）
- ムーブメントは戦闘の前に毎回、全部外してからはめ直す（武器の進化で盤が広がるので、武器を先に整える）
- GitHub Actions の `.github/workflows/measure.yml`（名前は「Measure」）。`main` への push と、手での実行（回数とシードを入力できる）で回る。結果は Summary に出る。手で実行できるのは `main` に入っているワークフローだけ
- 最初の測定（200周、シード1、2026-10-07）：1回目で勝てた割合は 戦闘1 100%、戦闘2 100%、戦闘3 97%、戦闘4 77%、ボス 42%（平均9.3ラウンド）。ボスは目安（約3割）より高い。段階9（調整1回目）の時の測り方（その場で書いた自動対戦、ギアのはめ方も別）とは方針の細部が違うこと、段階10で記憶の欠片が細かくなり、でたらめに吸わせた時に武器の育ち方が平らになったことが考えられる。数値の調整はこの段階ではしない（開発者と相談して決める）
