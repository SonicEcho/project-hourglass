## 進め方の約束（開発者との取り決め）

- 仕組みは `docs/design/` に従い、作業は `docs/milestones/` の段階単位で進める。仕様と違う判断や、仕様にないことを決めたら、関係する設計書の「決定の記録」に書く
- 大きな変更は、先に `docs/milestones/` の文書（または設計書）にたたき台を書いて確認してもらってから作る
- 長い文書は、チャットには要点と確かめてほしいことだけを短く書き、中身は GitHub で読んでもらう（トークンの節約）
- ユーザーへの文章はすべて日本語。作業後は「何を変えたか」と「スマホで何を確認すればよいか（具体的な操作手順）」を添える
- 作業ブランチはセッションごとに指定される名前に従う。PR がマージ済みなら、最新の `main` から作り直してから作業する
- 「マージしてください」と言われたら：PR を作る → ブランチの Actions の成功を確かめる → マージ → `main` の公開の成功を確かめる → ブランチを `main` にそろえる。Actions は決め打ちで長く待たず、終わったらすぐ次へ（1回はおよそ2分）
- 数値の調整は、自動対戦で勝率を測ってから決める（`npm run measure`。`-- --runs 300 --seed 1` で回数とシード）

## 確かめ方のコツ

- `npx tsc --noEmit`、`npx vitest run`、`npm run build`、`npm run e2e`（通しの自動確認、約1分）がすべて通ってからコミットする
- `src/` に新しい漢字などを書いたら `python3 scripts/font-subset.py` で見出しの書体を作り直す（`pip install fonttools brotli`。忘れるとテストが失敗する）
- 見た目を変えたら `node scripts/screens.mjs <フォルダ>`（`npm run build` の後）で主な画面を撮って見比べる
- `src/data` を変えたら `npm run data:tables` で `docs/data/` の表を作り直す（忘れるとテストが失敗する）
- 画面の確認：`npm run build` の後、Playwright（`vite` の `preview` を使う。`scripts/e2e.mjs` が手本）で 390×844 のスクリーンショットを撮る。テスト用の窓口 `window.__restopia`（`findText`・`scenes`）でボタンの位置を探してタップできる
- e2e は、初めての人向けの説明を全部見たことにして通す（`restopia.tips`）。説明を足したら、`src/data/tips.ts` の `id: '...'` の形を崩さない
- `?debug=1` の DBG メニュー：自動で1ラウンド戦う、敵のHPを1にする、つながりゲージを満タン、素材を全種類もらう、出来事へ飛ぶ、セーブを見る・消す、など
- 注意：`pkill -f "vite preview"` を起動と同じコマンドに書くと、自分のシェルまで止まる。止める時は別のコマンドで `pkill -f "[v]ite preview --port 4173"`
