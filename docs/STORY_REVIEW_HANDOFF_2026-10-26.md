## 1. この文書の位置づけと、開発者からの依頼

開発者は、物語の引力、完走したくなる理由、謎の回収、人物、ラスボス、結末の満足感まで踏み込んだレビューについて、「どれも的を得てて共感できる部分ばかり」「今後この先を開発していく上で、ちゃんとこれらのことを考慮しながらストーリー設計できるよう」に引き継ぐことを依頼した。

**レビューの観点を、今後の物語設計で継続して考慮する。具体的な改稿案や結末変更がすべて承認された、とは扱わない。** この文書を理由に、真のエンディングの削除、写しの設定変更、全編の台詞の書き換え等を即実施しない。

- 既存の決定：`docs/STORY.md`、`docs/CONCEPT.md`、関係する設計書・マイルストーン・脚本を現行版で確認する。
- 今回採用する設計上の姿勢：以下の強みを残し、レビューの懸念を検討・記録しながら章と結末を設計する。
- 未決定の具体策：本書の案を比較材料にして、接続する既存仕様と影響を具体化してから決める。選択肢の列挙を、同時実装の命令と解釈しない。
- 第4章以降の評価は設計段階のもの。台詞・演出・実機通しプレイで効果を確認した、とは書かない。レビューの見込みと、試読・試遊の事実を分ける。
- 同日作成の `docs/REVIEW_HANDOFF_2026-10-26.md` はゲーム全般の100項目。本書はその物語項目56〜67等を深掘りする補足。保存等の修正依頼を置き換えず、相互参照して使う。
- この文書を新設し、引き継ぎの参照先へ追加する作業であり、現時点で `STORY.md` の結末・ゲーム台本・ルート分岐を変更したものではない。

### Claude Codeが毎回行うこと

1. `CLAUDE.md` と `docs/HANDOFF.md` を読み、物語に関わる仕事では本書も参照する。基準コミット以降の変更・ユーザーの最新指示を優先する。
2. 今回依頼された章・段階を特定し、関係する本書の項目を選ぶ。全編改稿へ広げない。
3. 既存の「脚本 → 確認 → 遊べる台本」の進め方を守る。段階は現在のマイルストーンの末尾を確認し、次の番号で内容・検証を先に記載する。既にある番号を本書の番号で置き換えない。
4. 本書と既存の決定の緊張を見つけたら、「現在の決定」「プレイヤーへの影響」「推奨する最小案」「保留しても進められる範囲」を示す。既定の物語を黙って上書きしない。
5. 承認済みの範囲と通常の台詞・構成の細部は、自律的に具体化する。結末や世界のルールに関わる重要な未決定だけを、具体的な設計案にして相談する。既に決まった事項の確認を繰り返さない。
6. 決まった内容は正となる設計書・脚本へ反映し、理由を決定の記録へ残す。本書だけを新しい仕様の保管場所にしない。未解決は未解決として追跡する。

## 2. 総評と、残すべき魅力

評価の中心：RESTOPIAには「最後まで付き合ってよかった」と思わせる強い土台がある。特に、りくの救出、小夜子との別れ、あかりの夏祭りの回収に大きな可能性がある。一方、通常の別れと真のエンディングの再会の関係、および後半に集中する真相・倫理・人物の山場の接続を整理する必要がある。

| 観点 | レビューの判断 |
| --- | --- |
| 序盤の引力 | 「楽しい時間が短いのは盗まれているから」という、身近な感覚から入れる発想が強い。 |
| 続ける理由 | りくを探す → 他人の記憶を返す → 写しの消滅を知る → 自分たちの相手について選ぶ、という意味の変化が良い。 |
| 人物への愛着 | 屋台、食事、写真、日記等の具体的な日常を重ねる方針が有望。 |
| 謎の回収 | りくの語りは、過去の文章の感情を変えられる強い仕掛け。ハルトの正体は、意外性より関係の見え直しを重視したい。 |
| ラスボス | 倒す理由は明確。収集家としての固有性と、他者と時間を共有できない空虚さを深めたい。 |
| 通常の結末 | あかりの「また来年」、小夜子の手紙、ノアと作る新しい時間には、それぞれ独立した満足の可能性がある。 |
| 真の結末 | 再会の喜びはあるが、通常の結末を下位扱いしない位置づけと、人物の連続性・小瓶の成立条件が課題。 |

### 改善しても壊さないもの

- 「楽しい時間はあっという間」「秒針が止まって見える」「デジャヴ」「知らない街の夢」を、現実の体験と謎へ結び付ける入口。
- プレイヤーが祭りを少し遊び、自分でも参加した思い出にするプロローグ。
- 金魚の名前、自転車、歯車、腕時計、写真、日記、冷めた紅茶など、過去と現在をつなぐ具体物。
- 返すことで持ち主の今の行動が少し変わること。言葉だけの「救われた」報告に置き換えない。
- 3-2の、思い出しても言えなかった言葉は残るが「楽しかった」と笑える結末。返却を万能の人生修正にしない。
- 仲間全員が同じ結論を最初から持たず、それぞれに異なる立場があること。
- りくの語り、ノアの視線、写真の袋二つ等、読み返すと意味が変わる伏線。
- りくの怒りから手を差し出すまで、ノアの倍速からゆっくり過ごすまで、小夜子の反復から「昨日」「明日」を持つまでの変化。
- ヴィクトは明確に倒すべき悪役とする既定方針。敵を深めるために全員を同じ悲しい過去へ還元しない。
- 世界を救った後に個人的な別れが残る、ラスボス戦 → 終章の配置。

狙う読後感の有力な方向は「すべてを取り戻せた」だけではなく、「取り戻せなかったものもあるが、一緒に過ごした時間は確かに残った」。これは真のエンディングを廃止する決定ではない。再会による希望と、失ったものへの敬意を両立するための評価軸とする。

### D05で具体的に答える質問

- 返すことで、記憶だけが戻るのか、過去の出来事も変わるのか。
- 最後の一回だけが本物へ返る場合、百年の反復や旅の記憶は誰にどう残るのか。
- 小瓶という物が本物の小夜子へ渡る仕組みは、他の返却にも適用できるか。
- 手紙が現代に存在するようになる場合、以前の歴史や記録はどう扱うか。
- ヴィクトを倒して時間が返っても、ノアの母等の死者が戻らないなら、その境界は何か。死者が戻るという変更を今回承認したわけではない。
- 自覚して外へ出られる写しの条件は何か。みおの友達や早瀬の妻に適用するとどうなるか。
- 返さず残した時間は、レストピアが役目を終えた後も存在できるか。
- 誰かの時間を使わずに小瓶で会える条件は何か。利用の限界や、何を救えないかも説明できるか。

これらは全てを会話で説明する依頼ではない。作者側の整合性を固め、感情の山で「それなら別の方法で救えたのでは」と疑問が勝たないようにするための確認である。

### 三つの通常の道

- **あかりの道**：プロローグへ戻り「終わらせたくない」が「また来年」へ変わる円環を生かす。本当の出会い等の本編の解答を、このルートだけの報酬にしない。
- **ノアの道**：新しい時間を自分たちで作る希望を描く。未来の一日が長く感じる回収を、早送りの変化から積み重ねる。現代の十年を離れる重さと、未来で生きたい理由の両方を具体化する。
- **小夜子の道**：手紙で「会えなくても、時間は相手の人生へ残った」を示す。その後どう生きたかが少し分かると深まる。「過去へ残る」は既に却下された案なので復活させない。戻れない相手との記憶を抱え、ハルトがこれからどう生きるかも見せる。
- 三つへ同量の悲劇を足して対称にしない。それぞれが欲しいものを選び、手放すものを理解し、その後を想像できることを重視する。

### 真のエンディング

現行の「裏ボス → 小瓶 → 夕暮れに時代を越えて会える」という希望と、返せなかった時間が仲間をつなぐ発想の良さは認める。そのうえで、S20〜26・D01〜06を解決する。名称変更、ルート選択との分離、救済範囲の調整等は検討案であり、今回確定していない。

「時間に制限があるから大切」という一文だけで、通常道の別れ・写しの人格・他の写しへの適用を解決したと扱わない。再会できるうれしさと、この旅で受け入れたものが両立しているかを評価する。

## 6. 今後の脚本案に必ず添える確認メモ

長い報告を毎回増やす必要はない。対象章に関連する項目だけ、次を簡潔に記録する。これは実行可能なコードのテストではなく、物語設計の確認である。

1. **読後に残す感情**：この話を終え、何を感じ、次に何を知りたくなるか。
2. **前と後の違い**：人物の行動・関係・捜索の選択肢のどれが変わるか。情報が増えただけになっていないか。
3. **好きになる具体的な時間**：失う前に、一緒に過ごしたと感じられる場面があるか。
4. **伏線と回収**：今回出すもの・回収するもの・まだ伏せるもの。気付いた人にも感情的に届くか。
5. **本人の意思**：ハルト、仲間、持ち主、写しのうち、誰が何を選ぶか。他人の成長のための道具になっていないか。
6. **行動の納得**：秘密を隠す、寄り道する、敵を赦す、別れる理由が本人の状況から説明できるか。
7. **既存のルールとの接続**：今回初めて必要になった例外は何か。他の人物へ当てはめても成立するか。
8. **各ルートへの影響**：全ルート共通の事実か、相手固有の感情か。小瓶の有無でも確認する。
9. **関連レビュー番号**：対応したS/D番号、対応内容、残った懸念。不要と判断した場合は短い理由。
10. **試読・試遊で確かめること**：場面・質問・観察点を具体化する。正解を誘導する感想募集にしない。

### 試読・試遊で聞く例

- 序盤：「どの人物の先が気になるか」「次に何を調べたいと思ったか」。
- 前半：「りくを探す話は進んだと感じたか。何が変わったか」。
- 真相：「予想していたか」と「分かった後に誰への見方が変わったか」を別々に聞く。
- 7章：「誰の気持ちも分かったか」「自分の選択を尊重されたか」「写し自身をどう感じたか」。
- 終章：「小夜子は何を望んでいたと思うか」「別れを納得したか、押し付けられたか」。
- 通常ED：「疑問が残ったか」「選んだ道を完成した結末と感じたか」。
- 真のED：「会えたのは誰だと思うか」「通常道への印象がどう変わったか」「自分が選んだ関係は残っていたか」。

悲しんだ人を「満足していない」、泣いた人を「設定にも納得した」と短絡しない。設定への納得、感情の強さ、人物の意思、選択への尊重、余韻を別々に確かめる。

## 7. 最初の引き継ぎ作業と、以後の進め方

1. まずコードや既存台本を変えず、D01〜06の現状と未接続部分を整理する。既に現行文書で解決済みなら、その出典を残す。
2. 優先して、通常／真の結末、写しの連続性、共通の謎の回収、返さない選択、記憶・物・寿命のルールを一つの比較可能な案にまとめる。レビューの懸念を解消する最小の変更を推奨し、変更しない場合の説明案も評価する。
3. 結末全体の確定を待たず進められる範囲は、次に依頼された章の場面案・会話・既存伏線の点検を続ける。ただし未決定ルールを前提とする伏線を勝手に確定しない。
4. 各章の脚本を出すたびに6節の短い確認メモを添え、承認された決定を設計書・脚本・実装へ段階的に反映する。
5. 章完成時と結末案完成時に本書へ戻り、今回の対処が別のルートや人物の問題を生んでいないか確認する。

### 状態管理

各S/D項目の結果は、関係するマイルストーンに番号付きで「検討中／案あり／決定済み／脚本反映／実装済み／試読・試遊確認済み／現状維持」と記録してよい。決定済みには出典を、現状維持には理由を添える。未解決の項目を、レビューを読んだだけで完了にしない。

## 8. 誤って進めないための注意

- 本書はレビューの継承であり、新しいエンディングの最終仕様書ではない。
- 「小夜子を生存させる」「母を蘇生する」「真のEDをなくす」「恋愛をなくす」「全員を救う」等の具体的な変更は決定していない。
- 写しを人格として扱う重さを、別人の同じ姿や単なる設定説明で解決しない。
- テーマを「別れを悲しむのは間違い」「長く生きたい願いは悪い」という道徳へ単純化しない。
- プレイヤーの選択を正解／不正解で採点する新システム、分岐の大量追加、説明台詞の増量を、安易な解決策にしない。
- 既存の却下案を無言で再導入しない。`STORY.md` の「やめた案」と最新指示を照合する。
- 物語レビューを口実に戦闘速度・ムーブメントのおまかせ・素材の推薦表示等の決定を戻さない。ゲーム全般の引き継ぎも参照する。
- 更新前の引き継ぎメモの概要が、現行の脚本と食い違うことがある。特に日数や「最後の打席」の取り返し時期は現行データと照合する。
- コミット・公開はその時点のユーザー指示と運用に従う。本書を追加しただけで、物語変更の公開まで指示されたとは扱わない。
