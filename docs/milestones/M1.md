# M1：垂直スライス（プロローグと1章の最初）

「このゲームはこういう遊び」が1回で伝わる、30〜45分の体験を製品の品質で作る。全体の道のりは `docs/ROADMAP.md`、物語は `docs/STORY.md` の 2-8〜2-12。

**完成の基準**：開発に関わっていない人5〜10人に遊んでもらい、「続きを遊びたいか」を聞く。どこで迷ったか・やめたかを記録する。結果しだいで、探索・日常・戦闘の比重や、育成を開放する順番を見直す。

**2026-10-08 段階分けを決定**（開発者と確認。前提の決まりは下の「決まったこと」）。次は段階21。

## 作業の進め方

- M0 と同じ：段階ごとに依頼し、各段階の終わりにスマホで確かめる。段階は、この文書に「依頼する内容」と「スマホで確かめること」を書いてから作る
- **いつでも通しで遊べる状態を保つ**：先に「流れの骨組み」を作り、まだできていない所は仮の画面（「ここで探索」と出て「次へ」で進む）でつなぐ。段階ごとに、仮の画面を本物に置き換えていく
- 絵と音は、各段階では仮の素材（図形・試作の絵・仮の BGM）で作り、製品に近い絵と音は段階31でまとめて入れる。開発者は、それまでの間に絵と曲を少しずつ作れる（何が要るかは段階21の脚本で一覧にする）
- 新しい仕組み（物語の進行・会話・日常・探索・時間を返す）は、作る段階で `docs/design/` に設計書を足す（`docs/design/README.md` の「探索・物語・時間を返す仕組みなどの設計書は、その仕組みを作る時に足す」）
- 1つの段階を a・b に分ける時は、同じブランチで続けて作り、両方終わってから `main` にマージする

### 段階21の詳細：脚本と、要る素材の一覧

`docs/ROADMAP.md` の「各マイルストーンの前に、その範囲の脚本を固める」。コードは書かない。

- `docs/script/M1.md` に、上の「スライスの流れ」の全場面の脚本を書く（場面、背景、出る人、台詞、選択肢、演出。台本のデータにそのまま写せる形）
- `docs/STORY.md` の伏線のうち、M1 で張るものを、どの台詞・どの場面に置くかを書く（ハルトだけカタカナ、入口を開けられるのはハルトだけ、時計屋の奥と夕暮れ、白い街の夢、写真のシャッター、あかりの金魚の袋2つの写真、時計の秒針、プロローグの語り、ノアの視線）
- 1-1 の持ち主（大学生と妹）の名前、1-1 の砂嵐とボスの固有の名前を、`docs/NAMING.md` に候補として出して決める
- 要る素材の一覧：立ち絵（誰の・どの表情）、背景、1枚絵、地図、敵の絵、BGM（どの場面に何曲）、効果音。開発者が絵と曲を作り始められるように、`docs/ART.md` の指示文の形で書く

### 段階22の詳細：会話の画面（製品の形）

段階16の試作（`ProtoDialogueScene`）を、本編で使える形にする。

- 台本のデータの形を決める（`src/data/` に場面ごと）：話す人と表情、本文、選択肢と分かれ先、演出の命令（背景を替える、立ち絵を出す・下げる、BGM・効果音、暗転・明転、画面を揺らす、1枚絵を出す、待つ）
- 台本を読み進める処理は `src/core/` に置いてテストする（選択肢、分かれ先、読んだ所の記録）
- 画面：文字送り、タップで全文 → 次へ、ログ、早送り（読んだ所だけ）、オート（一定の間で進む）
- **名前の札のない語りの文**：文字の上を細かい砂がさらさら流れる演出と、砂の落ちる効果音（プロローグ用。6章で同じ演出に「りく」の札が付く形にしておく）
- `?debug=1` のデバッグメニューから、どの場面でも開ける

作ったもの（2026-10-08）：
- 台本は、脚本と同じ書き方の文字で `src/data/scriptM1.ts` に書き、`src/core/script.ts` で読み取って進める（書き方は `docs/design/dialogue.md`）。M1 の会話の場面（24場面と、探索中に話せる写し3つ）を全部写した
- 屋台めぐり・射的・金魚すくい（段階24）、探索と戦闘（段階25〜）、コマの表示（段階28）の所は、「開発メモ」の仮の案内と、選択肢で代わりに進める（射的の当たり外れ、景品、金魚すくいの結果、金魚の名前を選べ、1日目の朝に出てくる）
- 絵がない背景・立ち絵・1枚絵は、色と名前で仮に描く（大人のハルトとあかりだけ、段階18a の立ち絵が出る）。台本の BGM は仮の2曲で代わりに流し、まだない効果音は鳴らさない
- 早送りは読んだ所だけ（`?debug=1` の時は読んでいない所も）。読んだ印はセーブとは別に保存する
- 段階16の会話の試作は、この画面に置き換えて消した

調整1（2026-10-08、開発者がスマホで見た感想から）：
- 背景・1枚絵・人の出入りが急に切り替わる → 重ねてふわっと替える
- 長い文が一瞬はみ出してから折り返す → 全文で先に折り返しを決める
- 文字が出るたびの短い音（逆転裁判のような、声の代わり）を試しに入れた。人ごとに高さと音色が違う。上の「文字音」で入り切り

調整2（2026-10-08）：紙芝居に見える、への案（A 立ち絵の芝居、B 感情のふきだし、C 背景を動かす、D 地図の上の小さなキャラの芝居、E 演出の命令）から、開発者が A・B・C・E を選んだ
- 表情に合わせた立ち絵の動き、頭の上のふきだし、背景がゆっくり寄る動きと空気（提灯の灯り・星・舞う砂）、寄る・色を抜く・ノイズの演出（`docs/design/dialogue.md`）
- D（地図の上で小さなキャラが動く会話）は、段階25（探索）で、探索の地図の上で会話の場面を演じる形で考える

調整3〜6（2026-10-08）：文字の音を大きく、出力先（スピーカー／Bluetooth）を選べるように、人ごとの音の大きさをそろえた。表情を増やし（足した表情の絵は段階31a で作る。それまでは近い表情の絵で代わりに出す）、台本の表情を全場面で付け直した

### 段階23の詳細：物語の流れの骨組み

スライス全体を、データで書いた「出来事の並び」として進める。

- 出来事の種類：会話の場面、昼の日常、探索の区画、時間を返す、日が変わる、「つづく」。データは `src/data/story.ts` の章 → 区画を広げて書く（どの出来事の次に何が来るか）
- 進み具合（`src/core/progress.ts`）に「今どの出来事か」を足す。何日目も、ここで進むようにする
- セーブの版3：今の出来事を覚える。版1・2のセーブ（試作の5戦）は引き継がない（開発者と決めた。古いセーブは読めないものとして扱い、タイトルでは「はじめから」だけを出す）
- まだできていない種類の出来事は、仮の画面（「ここで探索（段階25で作る）」と「次へ」）で通す
- タイトルの「はじめる」をスライスの流れにする。今の試作の5戦は、デバッグメニューから遊べるように残す（自動対戦の測定と通しの自動確認がまだ使うため）
- 通しの自動確認（`npm run e2e`）にスライスの流れを足す
- 設計書：`docs/design/run.md` を書き直す（物語の進行、セーブの版3）

### 段階24の詳細：昼の日常

`docs/ART.md` の「日常の街：場面を選んで移動する形」。

- 場面（学校・商店街・時計屋）の1枚絵（仮）と、場面の間の移動（地図から選ぶ）
- 場面に、話せる人・見られる出来事の印を出す。絆の出来事（あかり1つ）と小話（1つ）
- 「夕暮れまで」の区切り：その日の必ず見る出来事を済ませると、夕暮れになって次へ進む（M1 では「誰と過ごすか」を選ぶ仕組みはまだ作らない。M2）
- 夕暮れの時計屋は、同じ背景を色の加工で茜色にして使う（`docs/ART.md`）
- プロローグの屋台めぐりも同じ仕組みで作る（参道の1枚絵に屋台の印、回った屋台に丸が付く「計画表」。`docs/script/M1.md` の P-3）
- タイミングでタップする小さな遊び2つ（射的：ゆれる的が真ん中に来た瞬間、金魚すくい：金魚が水面に近づいて光った瞬間）。失敗しても話は進む（おまけをもらえる）。射的の景品と金魚の名前の選択を覚えておき、1-A で施設の台所に出す。遊びの判定は `src/core/` に置いてテストする
- 設計書：`docs/design/daily.md` を足す

### 段階25の詳細：探索（製品の形）

段階16・18b の試作（`ProtoExploreScene`、`src/core/grid.ts`）を、本編で使える形にする。

- 区画のデータ（地図の絵、歩ける場所の文字の地図、宝箱、チェックポイント、敵の印と動き方、ボスの印、出口）
- 探索の状態（いる場所、開けた宝箱、倒した敵の印）を `src/core/` に置いてテストする
- 敵の印に触れる → 戦闘 → 勝てば探索の同じ場所に戻る（倒した印は消える）。負けた時はチェックポイントから
- 宝箱：素材・アイテムが本当に持ち物に入る
- チェックポイント：記録（セーブ）と、HP・MP の回復、育成の画面への入口（段階26）
- 探索の途中も自動でセーブし、閉じても続きから遊べる
- 縁日の地図は段階18b の絵をそのまま使う（作り直した絵は段階31a）
- 設計書：`docs/design/explore.md` を足す

### 段階26の詳細：パーティと育成の開放

- 1章のパーティは、ハルトとあかりの2人（みおの加入は2章。開発者と決めた）

### 段階27の詳細：平成の縁日の砂嵐と、区画のボス

- 平成の終わりの縁日の砂嵐（金魚・水風船・お面などがノイズで崩れて混ざった姿。`docs/STORY.md` の 2-5）を3〜4種類。試作のスライムなどの数値と仕組み（弱点・耐性）を元にしてよい
- 区画の奥のボス（1-1 の山場。部位破壊と大技の予告を、ここで覚えてもらう）
- 固有の名前は段階21で決めたものを使う（`docs/NAMING.md`）
- 砂嵐は、コマ（返すのに使う）と素材（育成に使う）を別々に落とす（開発者と決めた）。素材は今の素材と同じ扱い（時分解して武器へ）
- 数値は自動対戦で測って決める（2人のパーティ、1-1 の流れ）。勝率の目安を開発者と決め、`docs/design/battle.md` に書く
- 設計書：`docs/design/battle.md` の今のボスの節を書き直す

### 段階28の詳細：コマ集めと、時間を返す

`docs/CONCEPT.md` の「ゲームの循環」と「返すことのルール」。

- 盗まれた時間（1-1「金魚の名前」）ごとに、返すのに要るコマの数を持つ（1-1 は、まず8つ。遊んで長さを見て直す）。砂嵐を倒すとコマが手に入る（素材とは別に。段階27）
- 探索の画面に「あとコマが◯つで返せる」を出す
- そろったら、区画の奥（または決まった場所）で「返す」を選べる → 返す場面の演出 → 夕暮れの時計屋へ
- コマは返すことだけに使う（素材と別にしたため。そろった後に余ったコマをどうするかは、作る時に決める）
- 前半なので、返すか残すかの選択肢は出さない（`docs/CONCEPT.md` の「設計上の注意」）
- 返した時間をセーブに残す（M2 の「翌日に持ち主に会う場面の型」と、8章の「持ち主たちが待っている」に使う）
- 設計書：`docs/design/return.md` を足す

### 段階29の詳細：雑魚戦のオートと早送り

`docs/CONCEPT.md` の「戦闘のメリハリ」。

- 雑魚戦の画面に「オート」。作戦を選べる（たたき台：「おまかせ」「弱点を突く」「守りを固める」「MP を使わない」）。作戦ごとの選び方は `src/sim/` の自動の方針を元に、`src/core/` か `src/sim/` に置いてテストする
- オート中も、画面をタップすればいつでも手動に戻せる
- 早送り（演出の速さ ×2・×3）。設定として覚える
- ボス戦ではオートを出さない（早送りは使える）
- 設計書：`docs/design/battle.md` に足す

### 段階30の詳細：初めての人向けの説明

- 戦闘：最初の数戦で、使う場面になった時に1つずつ（行動を選ぶ → 実行、弱点とダウン、延長、コンボ、バトンタッチ、部位破壊と大技の予告）。説明の通りに操作させる所は最小限にする
- 探索・コマ集め・星図・武器も、初めて開いた時に短く
- 見た説明を覚えて、2回目からは出さない（セーブとは別に覚えるか、セーブに入れるかは作る時に決める）。タイトルかメニューから読み返せる
- 説明の文は `src/data/` にまとめる
