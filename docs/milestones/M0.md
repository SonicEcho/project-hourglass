# M0：本格開発の土台

試作のコードを、長く育てられる形に整える。遊びの中身はほぼ増やさない。全体の道のりは `docs/ROADMAP.md`。

**完成の基準**：今の試作と同じ遊びが、新しい土台の上で動く。途中で閉じても続きから遊べる。

## 作業の進め方

- 一度に全部を頼まず、段階ごとに依頼し、各段階の終わりにスマホで動作を確かめる
- 段階は、この文書に「依頼する内容」と「スマホで確かめること」を書いてから作る。大きな変更は、先にたたき台を書いて開発者に確かめてもらう
- 仕組みを変えたら、`docs/design/` の設計書を上書きし、「決定の記録」に理由を残す
- 1つの段階を a・b に分ける時は、同じブランチで続けて作り、両方終わってから `main` にマージする（途中で公開が壊れないように）
- 開発者に「マージしてください」と言われたら、PR を作り、ブランチの GitHub Actions が通っているのを確かめてから `main` にマージする

### 段階18の詳細：絵の見本（立ち絵と、見下ろしのマップ）

M0 の「絵と音の方向性」で、すべてイラスト（AI で作る）と決めた（`docs/ART.md`）。本当にゲームの画面で使えるかを、段階16の試作の画面に絵を入れて、スマホで確かめる。絵はすべて仮の素材（`placeholder`）として台帳に入れる。

**18a：会話に立ち絵**

- 開発者が作ったあかりの胸から上の絵5枚（笑顔・大笑い・心配・むっ・デジャヴ。見本は ChatGPT、表情違いは Gemini。どちらも無料の版）を、白い背景を透明に抜いて `public/assets/portraits/` に置く（WebP）
- 背景を抜く処理は `scripts/cutout.py`。最初は色の近さで抜いたが、髪のまわりに白いふちが残ったので、アニメ向けの背景を抜く AI（rembg の isnet-anime）に変えた
- 台帳に5枚を書く：サービス名、無料の版、指示文、見本にした絵、作った日。規約の控えは `docs/licenses/ai-gemini.md`・`docs/licenses/ai-openai.md`（調べた日の要点と URL）
- 会話の試作で、あかりの図形の枠を立ち絵に置き換える。台本の行ごとに表情を書き、話す行で差し替える。話していない時は暗くする（重なっても透けないよう、薄くするのではなく暗くする）。ゆっくり息をするように、わずかに伸び縮みさせる
- 絵が読み込めない時は、今までの図形で描く（段階15の決まり）
- ハルトも、開発者が ChatGPT で作った表情4つ（通常・やさしい笑顔・驚き・決意）の一覧から切り出して入れる（2026-10-08 に追加）。顔と肩の正方形の絵で、あかりと構図が違うので、本番では同じ構図（胸から上の縦長）で作る

**18b：見下ろしのマップ**

- Gemini で作った縁日の見下ろしの絵（1-1「金魚の名前」）を、探索の試作の地図にする。歩ける場所は、絵に合わせて文字の地図（見えないマス目）で書く。くわしくは 18a の確認の後に書く

### 段階17の詳細：データの一覧表と、つながりの確認

`docs/ROADMAP.md` の「データの定義をまとめ直す（表で書いて読み込む形に）」について、開発者と相談して次の形に決めた（2026-10-07）。

- **データは今のまま TypeScript（`src/data/`）で書く**。型とテストで書き間違いをすぐ見つけられるため。数値を変える時は、今までどおり Claude に頼む
- **表は、データから自動で作る**。GitHub のスマホの画面で、表として読めるようにする

**一覧表**（`docs/data/`。手で書き換えない）

| ファイル | 中身 |
| --- | --- |
| `README.md` | 一覧と、作り方 |
| `characters.md` | 仲間（能力値、最初の魔法・スキル）と、魔法・スキル（MP、効果、重さ。星図で覚えるものを含む） |
| `snaps.md` | スナップ（アルバムの枚数、効果、重さ）、コンボ、連携技 |
| `enemies.md` | 敵（能力値、弱点・耐性、行動、落とす素材）、部位、周回の戦闘（敵、星の砂、アイテム、ギアの候補） |
| `growth.md` | 星図のマス（種類ごとの数と費用）、ムーブメントのギア（色、マス数、効果）と盤 |
| `weapons.md` | 武器と進化先（条件、効果）、素材・アイテム（時分解すると何になるか）、記憶の欠片 |

- 作る命令は `npm run data:tables`。説明の文は、画面と同じ処理（`src/ui/describe.ts` など）で作る
- テストが、`docs/data/` の表が今のデータと同じかを確かめる。データを変えて表を作り直し忘れたら、テストが失敗して公開されない（表がいつも正しい）

**データのつながりの確認**（テスト）

- 名前（id）がそろっている（表の中のキーと、中身の id が同じ）
- 参照している名前が本当にある：敵が落とす素材、戦闘でもらえるアイテムとギアの候補、最初に持っているギア、ボスの部位のギア、アルバムのスナップ、コンボの材料、連携技の仲間、星図のマスの魔法・スキルと出発点、武器の持ち主と進化先、素材・アイテムから出る記憶の欠片、仲間ごとの盤
- 仲間1人に武器1本、盤1枚

### 段階16の詳細：エンジンを決めるための試作（探索と会話の画面）

M1（垂直スライス）では、戦闘のほかに「裏側の街の探索」と「会話」の画面が要る。今の Phaser 3 で、この2つが無理なく・滑らかに作れるかを、小さな試作で確かめてから、エンジンを続けるかを決める（`docs/ROADMAP.md` の M0「エンジン」）。試作はゲームの本編には入れず、`?debug=1` のデバッグメニューから開く。絵は図形の仮のまま、物語の正式な台詞も書かない。

**探索の試作**

- 区画の仮のマップ（24×36マス、1マス32）を、壁・通路・部屋で作る。画面より大きく、カメラが仲間について動く
- 画面をタップすると、その場所まで最短の道を歩く（壁をよける）。道を探す処理は `src/core/grid.ts` に置いてテストする（M1 の探索でもそのまま使う）
- 宝箱：触れると開き、「素材を手に入れた（試作なので持ち物には入らない）」と出る
- 敵の印：決まった道を行き来する。触れると「遭遇！」と出る（試作なので戦闘には入らない）
- チェックポイント：触れると「ここで記録した」と出る
- 右上に、1秒あたりのコマ数（FPS）を出す。「戻る」でタイトルへ

**会話の試作**

- 背景、2人の立ち絵の枠（図形と名前）、名前の札、本文の枠
- 本文は1文字ずつ出す（文字送り）。タップで全文を出し、もう一度タップで次へ。話している人の立ち絵を明るくする
- 選択肢（2つ）で、その後の文が分かれる
- 「ログ」で読み返し、「早送り」で読んだ所を飛ばす
- 台本は `src/data/` に仮の文で書く（データの形を確かめるため。物語の正式な台詞ではない）

**決める時の目安**（開発者のスマホで触ってもらう）

| 目安 | 見ること |
| --- | --- |
| 滑らかさ | 探索で歩いている時、FPS がだいたい55以上を保てるか。かくつかないか |
| 文字 | 会話の文字がにじまず読みやすいか。文字送りが気持ちいいか |
| 手触り | タップで歩く操作、会話を進める操作に、ストレスがないか |
| 作りやすさ | Phaser の機能で足りたか（Claude からの報告：足りなかった所、手間がかかった所） |

結果と決定は `docs/design/tech.md` の「決定の記録」に残す。

### 段階15の詳細：素材台帳と、素材を読み込む部品

買い切りで売るので、使う素材はすべて「売り物に使ってよいか」を確かめられる状態にしておく（`docs/ROADMAP.md` の「絵と音の素材の管理」）。今は画像・音の素材はなく（絵は図形、文字は端末のフォント）、配布物に入っている他の人の作品はライブラリ（Phaser、eruda）だけ。絵と音を入れ始める前に、仕組みを先に作る。

**台帳**

- 台帳の正は `src/data/assets.ts`（プログラムが読む形）。クレジットの画面とテストが同じ台帳を読む。`docs/ASSETS.md` には、素材を手に入れる時の決まり・台帳への書き方・公開前の確認を書く（表は写さない）
- 素材ごとに書くこと：名前（id）、種類（画像・音・フォント・ライブラリ）、ファイルの場所、仮か本番か、入手元（自作／フリー素材のサイト名と URL／AI のサービス名と有料・無料の版／ライブラリ）、ライセンスの名前、売り物に使えるか、作者名の表示（クレジット）が要るか とその文、改変してよいか、手に入れた日、手に入れた時の利用規約の控えの場所、AI で作った時は使った指示（プロンプト）と設定、メモ
- 今の台帳：ライブラリ2つ（Phaser、eruda）と、仕組みを確かめるための自作の素材1つ（タイトルの砂時計の絵。今の図形と同じ見た目の SVG、仮の素材）

**テスト**（台帳の書き漏れを、公開の前に自動で止める）

- id が重ならない。画像・音・フォントはファイルが `public/assets/` にある
- クレジットが要るものは、その文がある。フリー素材は URL と規約の控えの場所がある。AI の素材はサービス名・版・プロンプトがある
- 本番の素材は、売り物に使えるものだけ。ライブラリは `package.json` に入っているものと合う

**素材を読み込む部品**

- 素材の読み込みを1か所（`src/assets/`）にまとめる。ゲームの始めに「起動」の画面で、台帳にある画像・音を読み込んでからタイトルへ進む
- 画面は台帳の id で素材を使う。ファイルがない・読み込めない時は、今までどおりの図形で代わりに描く（素材がなくてもゲームが止まらない。仮と本番の差し替えはファイルと台帳を変えるだけ）
- 読み込めなかった素材は、コンソールに `[assets]` 付きで出す

**クレジットの画面**

- タイトルの下に小さく「クレジット」。押すと、素材とライブラリの一覧（名前、作者、ライセンス、クレジットの文）を出す。「タイトルへ」で戻る。台帳から自動で作る
- `?debug=1` の時は、各素材に「仮／本番」と入手元も出す（差し替え忘れを見つけやすく）
