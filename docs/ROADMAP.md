# 本格開発のマイルストーン

2026-10-06 時点のたたき台。試作（`docs/SPEC.md` の段階1〜9）の結果を受けて、製品版までの道のりを整理する。期間・人数はまだ決まっていないので、日付は入れていない。

## 0. 出発点：試作でわかったこと

| 確かめたこと | 結果 |
| --- | --- |
| 戦闘（ラウンド制、共通の手札、コンボ、弱点・ワンモア・バトン、連携技、部位破壊、大技の予告） | 段階6でCTBからラウンド制へ作り直した。ボスの手応えは「ちょうどいい」 |
| 育成1：成長マップ（量の成長） | 確認済み。気になる点なし |
| 育成2：ナビカス盤（詰めて組み合わせる成長） | 「いい感じのバランスで面白かった」 |
| 育成3：武器ビルドアップ（育てて分岐する成長）＋素材の断片化 | 実装済み。遊んだ感想はこれから |
| スマホ縦持ち・片手の操作 | 戦闘・3つの育成の画面とも、タップと長押しで組めた |
| 数値の決め方 | 自動対戦で勝率を測ってから決めるやり方が使えた |

**まだ確かめていないこと（本格開発で一番の不安）**

- 物語・探索・日常パートと組み合わせた時に、1回の遊び（数分〜30分）が気持ちよく区切れるか
- 修復と代償の仕組みが、遊びとして楽しく、物語として刺さるか
- 育成の仕組みが4つ重なった時に、初めての人が迷わないか（段階的な開放でさばけるか）
- 絵と音が入った時の見た目と手触り（いまは図形と文字だけ）

## 1. 進め方の方針

- **縦に切って作る**：仕組みを横に広げる前に、「1区画を製品の品質で」遊べる形（垂直スライス）を先に作り、外の人に遊んでもらう
- **章ごとに積む**：その後は、物語の章の順に作る。各章の終わりで、通しで遊べる状態にする
- **今の作り方を引き継ぐ**：`src/core` は Phaser に依存させない、数値は `src/data`、乱数はシード付き、テストが通らなければ公開しない、数値は自動対戦で測って決める
- **仕様書の分け方を変える**：`docs/SPEC.md` は試作の記録として残す。本格開発では、仕組みごとの設計書（戦闘・育成・探索・物語・修復など）と、マイルストーンごとの作業の一覧に分ける

## 2. マイルストーン

### M0：本格開発の土台

試作のコードを、長く育てられる形に整える。遊びの中身はほぼ増やさない。

- **決めること**
  - 配布の形：Webのまま（PWA）か、アプリにするか（Capacitor などで包む）。課金の有無
  - エンジン：Phaser 3 を続けるか（探索や会話の画面まで作れるか、を小さく試してから決める）
  - 用語と名前：ナビカス盤・スフィア盤・CTB など、参考作品の名前をそのまま使っている用語を独自の名前にする。キャラ名（いまは仮）も確定する
  - 絵と音の方向性（担当者、外注か自作か、解像度とスタイル）
- **作るもの**
  - セーブ・ロード（版の番号付き。データの形が変わっても古いセーブを読めるように）。中断・再開（まずは戦闘の外だけ）
  - データの定義をまとめ直す（キャラ・敵・カード・パーツ・武器・素材を、表で書いて読み込む形に。数が増えても管理できるように）
  - 画面の移り変わりと状態の持ち方を整理（今の `run.ts` を、章・日・区画を持てる形に）
  - 自動対戦の勝率測定をスクリプトにして、いつでも回せるようにする
  - 設計書の分割（上の「仕様書の分け方」）
- **完成の基準**：今の試作と同じ遊びが、新しい土台の上で動く。途中で閉じても続きから遊べる

### M1：垂直スライス（第1章の最初の1区画）

「このゲームはこういう遊び」が1回で伝わる、15〜30分の体験を製品の品質で作る。

- **作るもの**
  - 物語の導入：記念祭の夜、ミライの信号で市の端末が暴走し、りくが消える（会話の画面、立ち絵の仮版）
  - 裏側の街の探索：1区画（移動、敵との遭遇、宝箱・素材、チェックポイント）
  - 区画の奥のボスと、修復1回（修復すると現実の街に店が戻る。代償は裏で発生するが、まだ見せない）
  - 昼の日常1枠（会話1つ、絆が少し進む）
  - 戦闘：今のものに加えて、雑魚戦のオート（作戦指定）と早送り
  - 育成：成長マップと武器だけを開放（構想ノートの「序盤は成長マップと武器だけ」）
  - 初めての人向けの説明（戦闘・育成を、遊びながら少しずつ覚える）
  - 絵と音：このスライスの範囲だけ、製品に近い品質で入れる
- **完成の基準**：開発に関わっていない人5〜10人に遊んでもらい、「続きを遊びたいか」を聞く。どこで迷ったか・やめたかを記録する
- **ここでの判断**：結果しだいで、探索・日常・修復の比重や、育成を開放する順番を見直す

### M2：第1章の完成（序盤：直すことの喜び）

- **作るもの**
  - 第1章の区画すべてと、章のボス（敵の種類を増やす。部位を持つ雑魚も入れて、素材を狙う理由を作る）
  - 仲間の加入：あかり・みお（加入時にナビカス盤を開放）
  - 章ごとのゆるい期限（1日＝昼の日常1枠＋夜の潜入1枠。遅れても終わらず、章の結末が変わる）
  - 修復の網（記憶ノード）の最初の形と、伏線の「小さな違和感」
  - フォルダ（デッキ）の編集、カードの入手
  - 周回・狩り（開放済みの区画で素材を集める。日数を使わない）
  - 戦闘中を含めた中断・再開
- **完成の基準**：第1章を通して遊べる（目安 2〜4時間）。章の結末の分かれ方を確かめる

### M3：中盤（転換：直すたびに誰かが消えていた）

- **作るもの**
  - 仲間の加入：久世・りく（りくは行動順やバグを扱う、癖のある盤）
  - 深層の区画と、りくとの再会・戦闘
  - 代償の開示（それまでの修復記録を「直したもの」「代わりに消えたもの」の一覧で見せる）
  - カード昇格（育成の4つ目。中盤に開放）
  - 連携技の追加（主人公×りく、みお×久世 など）と、3人技の最初の1つ（主人公×あかり×みお）
  - 総攻撃・トランスなど、戦闘の残りの要素から必要なもの
- **完成の基準**：第1章から中盤の転換まで通して遊べる。転換で「序盤の喜びが罪悪感に反転する」体験が成立しているかを、遊んだ人の反応で確かめる

### M4：後半〜終盤（選ぶ物語へ）

- **作るもの**
  - 代償を見て選ぶ修復（直す・直さない・歪みを狩って埋める・人とのつながりで支える）
  - 過去の層（ソラ）と未来の層（ミライ）、記録局との対立
  - 仲間それぞれのサイドストーリーと絆、ヒロインのルート
  - マルチエンディングと周回（真のエンディング）
  - 残りの連携技・3人技（ソラ×あかり×ミライ など）
- **完成の基準**：全章を通して遊べる。どの結末にも、それまでの選択の結果として納得できる道がある（明らかな正解を作らない）

### M5：磨き込みと公開

- 全体のバランス調整（自動対戦と、人に遊んでもらう試遊の両方）
- 初めての人向けの説明、遊びやすさの設定（文字の大きさ、色の見分けやすさ、早送りなど）
- 端末ごとの確認（古いスマホでの速さ、画面の大きさの違い、電池の減り）
- 法務の確認：用語・名前の最終確認、必要なら仕組みの特許の確認（弁理士への相談）、使う素材の権利
- 公開の準備（ストアの申請、紹介ページ、不具合を受け付ける窓口）

## 3. マイルストーンをまたいで進めること

| 流れ | 内容 | 始める時期 |
| --- | --- | --- |
| 物語・脚本 | 章ごとの筋、会話、伏線と代償の対応表（何を直すと誰の何が消えるか） | M0 から。各マイルストーンの前に、その範囲の脚本を固める |
| 絵・音 | 方向性 → スライスの範囲 → 章ごとに量産 | M0 で方向性、M1 で最初の製品品質 |
| 数値の調整 | 自動対戦の測定を各マイルストーンの終わりに回す。成長の量（育成4つ分）の上限を決めておく | ずっと |
| 試遊 | 開発に関わっていない人に遊んでもらう | M1 から、各マイルストーンの終わりに |
| 技術 | セーブの版の管理、性能、端末対応 | M0 から |

## 4. すぐに決めたいこと

1. **配布の形**（Web/PWA かアプリか）と、課金の有無。セーブの作り方や画面の作り方が変わる
2. **体制と期間**：何人で、どのくらいの期間で作るか。これでマイルストーンの大きさ（特に M2 以降の章の数）を決める
3. **絵と音の方向性**：誰が作るか、どんな見た目にするか
4. **用語と名前の確定**：公開前でなく、M0 で決めておくと後の書き直しが少ない

## 5. 次の一歩（M0 の最初の作業の候補）

- セーブ・ロード（版の番号付き）と中断・再開（戦闘の外）
- 自動対戦の勝率測定をスクリプトにする
- 設計書の分け方を決めて、`docs/SPEC.md` から戦闘・育成の設計書を切り出す
