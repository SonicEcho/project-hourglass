# 設計書：技術・テスト・デバッグ

## 1. 技術の構成

| 項目 | 使うもの | 用途 |
| --- | --- | --- |
| 言語 | TypeScript | 型で壊れにくくする |
| ビルド | Vite（`base` は `/project-hourglass/`） | 開発と本番ビルド |
| 描画 | Phaser 3 | 2Dの画面、タップ操作、アニメーション |
| テスト | Vitest | ロジックの自動テスト |
| CI・公開 | GitHub Actions → GitHub Pages | push でテストし、通れば `main` だけ公開 |
| スマホ用ログ | eruda（`?debug=1` の時だけ読み込む） | スマホのブラウザでエラーやログを見る |

- Node.js は 22
- 画面は縦持ち 390×844 を基準に、Phaser の Scale FIT で合わせる。高解像度のスマホでにじまないよう、内部は端末の画素密度（最大3倍）で描き、座標は 390×844 のまま
- サーバーは使わない（買い切りでオフラインでも遊べるように。`docs/ROADMAP.md`）
- エンジンは Phaser 3 を続ける（段階16の試作で決めた。下の「決定の記録」）

## 3. 設計の原則

- **ロジックと画面を分ける**：`src/core` は Phaser を一切読み込まない。自動テストで確かめられる形にする
- **データはコードから分ける**：数値は `src/data` に TypeScript で書く（型とテストで書き間違いを見つける）。表で見たい時は `docs/data/` の一覧表を見る（`npm run data:tables` で自動で作る）
- **乱数はシードで再現できる**：乱数は mulberry32。戦闘の状態に乱数の内部状態も持つ。URL の `?seed=数字` で固定できる
- **戦闘の出来事は記録に残す**：すべて `state.log` に構造化して残し、演出・戦闘ログ・行動の回数に使う
- **保存の場所・素材の読み込みは1か所にまとめる**：Web とアプリで差し替えられるように
- **素材がなくても止まらない**：ゲームの始めの「起動」の画面（`BootScene`）でタイトルに要る素材（SVG・効果音）だけを読み込み、絵（立ち絵・背景・地図・1枚絵・敵）はタイトルを出した後に、ずっと動いている読み込み専用の画面（`PreloadScene`）が裏で読む（段階69）。タイトルから遊び始める時は、読み終えるまで待つ（曲を端末にしまうのと同じ待ちの画面）。画面は台帳の id で素材を使い（`addImageOr`）、読み込めない時は図形で代わりに描く。読めなかった素材はコンソールに `[assets]` 付きで出す

## 4. テスト

- `npm test` で全部。`src/core` を変えたら、必ず `tests/` のテストを足す・直す
- データのつながり（`tests/dataRefs.test.ts`。敵が落とす素材、戦闘の報酬、コンボの材料、星図のマスなどが、本当にある名前を指しているか）と、一覧表が今のデータと同じか（`tests/dataTables.test.ts`。データを変えて `npm run data:tables` を忘れると失敗する）
- 素材台帳の書き漏れ（`tests/assets.test.ts`。ファイルがない、クレジットの文がない、規約の控えがない、本番なのに売り物に使えない、ライブラリが `package.json` と合わない）
- ロジック（戦闘・星図・ムーブメント・武器・進み具合・セーブ）、データの整合（`tests/data.test.ts` など）、Phaser に依存しない補助関数（デバッグ判定、ビルド情報、スキルの並べ方）、自動対戦（`tests/sim.test.ts`）
- **通しの自動確認**（`npm run e2e`、`scripts/e2e.mjs`。段階20）：`npm run build` した公開物を手元のサーバーで開き、Playwright の Chromium で自動で遊ぶ。タイトル →「はじめる」→ 戦闘1〜5（デバッグの「敵のHPを1にする」と「自動で1ラウンド戦う」で進める）→ 結果。戦闘2の後にページを開き直して「つづきから」で続くか、BGM が流れて縁日の試作で切り替わるか、戦闘で戦闘の曲（ボスはボス戦の曲）になるかも見る。エラーが出たり止まったりしたら失敗し、その時の画面を `e2e-failure.png` に残す。1回およそ1分
  - 画面は canvas なので、ボタンは文字の位置を `window.__restopia.findText()` で調べてタップする。画面の文字を変えたら、`scripts/e2e.mjs` の探す文字も合わせる
  - 演出の見た目を撮る時は、`window.__restopia.start(画面, データ)` で画面を直接開き、`window.__restopia.scene(画面)` で演出を外から呼べる（段階46）
- コミットの前に `npm test`、`npx tsc --noEmit`、`npm run build` が通ること。`npm run e2e` は、画面の移り変わり・保存・物語の流れ・e2e が押すボタンの文字を変えた時に手元でも通す。それ以外（文書だけ、1つの画面の見た目・文字だけ）は手元では回さず、push 後の GitHub Actions の e2e の結果を確かめる（失敗したらすぐ直す。失敗した版は公開されない）

## 5. 自動対戦の測定

- `npm run measure`（`-- --runs 200 --seed 1` で回数とシード）。結果は戦闘ごとの「1回目で勝てた割合」「平均ラウンド」「平均やり直し」の表。同じ回数・シードなら同じ結果。200周で約20秒（1-1 の表を含めて約30秒）
- GitHub Actions の「Measure」（`.github/workflows/measure.yml`）：`main` への push と手での実行で回り、結果は Summary に出る。公開とは別。push では60回、手で回す時の初期値は200回。90分で止める
- 自動の方針（`src/sim/`）

| 場面 | 方針 |
| --- | --- |
| 戦闘 | 候補の先頭5つからでたらめに選ぶ。サポートは半分の確率で使う。追加行動は3回に1回バトンタッチ |
| 星図 | でたらめなキャラの、開けられるでたらめなマスに、払えなくなるまで使う |
| ギアの報酬 | 候補の先頭から選ぶ |
| ムーブメント | 戦闘の前に全部外し、大きいギアから順に、効果ギアはブリッジ優先、狂いを作らない場所へ。キャラは順番に回す |
| 武器 | 仲間を順番に回し、一番近い進化先に近づく素材から刻む（枠がいっぱいになるまで。鍵の素材は残す）。残りは時分解し、欠片をでたらめな仲間へ。進化できれば最初の進化先（`src/sim/autoArmory.ts`。段階27b） |
| 負けた時 | 育成はそのまま、同じ戦闘を別のシードでやり直す（最大20回） |

- **1-1 の縁日の表**（段階27。`src/sim/autoArea.ts`）：章のパーティ（ハルトとあかり）で、区画の戦闘を出会う順（敵の印の並び → ボス）に戦う。最初の戦闘の後に宝箱を2つとも開ける。星図はパーティの中ででたらめ、武器は上の表と同じ、ムーブメントはなし。つながりゲージは戦闘をまたいで引き継ぐ。戦闘の方針を2つ出す。段階37で 1-2、段階39で 2-1 の表を足した（先の区画を同じ方針で通した後から。区画ごとに、物語のその章のパーティで戦う（`areaLineup`。2-1 はみおを入れた3人）。ムーブメントの開いた章では、区画のごほうびのギアを入ってすぐもらったものとし、戦闘の前に `arrangeNavi`（試作の5戦と同じ置き方）ではめ直す）
  - ほぼでたらめ：上の表と同じ
  - 弱点をねらう（`src/sim/autoBattle.ts` の `smartPlay`）：敵の本当の弱点を突く行動を最優先。なければ、力をためている敵がいる時は防御、弱点が隠れた部位を狙う、の順。連携技は体勢が崩れた敵がいる時だけ。追加行動は弱点を突ければ突き、なければ半分の確率でバトンタッチ
- 数値を変える時は、測ってから決める。測った結果は、変えた設計書の「決定の記録」に残す

## 6. デバッグ（スマホで確かめるため）

- 開発者はスマホのブラウザで公開URLを開いて確かめる。PCの開発者ツールは使えない前提
- 画面右下に、ビルドした日時（日本時間）とコミットの短いIDを出す（`YYYY-MM-DD HH:mm JST (abc1234)`。`?debug=1` の時は先頭に `[debug]`）
- `?debug=1` の時だけ、eruda と、左下の「DBG」から開くデバッグメニュー（Phaser の外の HTML。`src/debug/debugMenu.ts`）と、その右の「メモ」を有効にする
- デバッグメニューは見出しごとに並べる（段階92）。よく使う「確認」と、その時だけの「戦闘中」「探索中」は開いたまま、ほかは押すと開く折りたたみ
  - **確認：出来事へ飛ぶ**：出来事と育ち具合（ふつう・控えめ・やり込み・育成はそのまま）を選んで飛ぶ（下の 9.）／次の出来事へ飛ばす／飛ぶ前のセーブに戻す・捨てる
  - **戦闘中**：味方を全回復／つながりゲージを満タン／自動で1ラウンド戦う／敵のHPを1にする（演出中は使えない）／戦闘のシードと戦闘ログ
  - **探索中**：敵の印を全部倒したことにする／ボスの手前へ／その晩のコマをそろえて帰り口へ
  - **育成の上乗せ**：星の砂 +10／ギア・スナップ・素材とアイテムを全種類／記憶の欠片／ポーチを満タン／仲間の武器を次の進化に要るレベルに
  - **設定**：物語の探索でもオートを出す／読んだ印を消す／シードの固定
  - **調べる**：会話の場面を選んで開く／プレイ時間の記録／セーブの中身を見る・消す／端末にしまった物
  - **古い試作**（本編では使わない。通しの自動確認で使う）：試作の5戦を最初から（シードを指定しても）／縁日のマップを歩く
- コンソールには `[battle]` `[save]` などの印を付けて出す

## 7. 公開

- `.github/workflows/deploy.yml`：すべてのブランチへの push でテストとビルド（PR の時は走らせない。push の結果が PR にも出るため）。Playwright のブラウザは版ごとに覚えておき（actions/cache）、毎回は入れ直さない。GitHub Pages への公開は `main` への push の時だけ。テスト・ビルド・通しの自動確認のどれか1つでも失敗したら公開しない（通しの自動確認が失敗した時の画面は、その実行の Artifacts の `e2e-failure` に残る）
- リポジトリの Settings → Pages の Source は「GitHub Actions」
- 公開URL：https://sonicecho.github.io/project-hourglass/
- **端末にしまう**（段階70）：Service Worker（`vite-plugin-pwa`。`vite.config.ts`）。一度開いたら、ゲーム全部（ページ・プログラム・絵・効果音・曲。約36MB。まばたき・口パクの元の絵 `*_src.webp` は除く）を裏で端末にしまい、2回目からはそこから読む。オフラインでも最後まで遊べる。新しい版を公開した後に開くと、変わったファイルだけを読み直してしまい直し、読み終えたらすぐ新しい版に切り替わる（`skipWaiting`・`clientsClaim`。段階76）。新しい版があるかは、開いた時と裏から戻った時に確かめる（`src/assets/serviceWorker.ts`）。開いている画面はそのまま動き、次に開いた時から新しい版になる（右下のコミットの短い ID で、どちらの版か分かる）。曲の URL の版の印（`?v=`）と、`?debug=1`・`?seed=` は無視して同じファイルとみなす。デバッグメニューの「端末にしまった物」で、しまった状態を見たり、全部消して取り直したりできる（セーブは消えない）。iPhone の Safari は、しばらく開かないサイトのデータ（しまった物とセーブ）を消すことがあるので、ホーム画面に追加して使う

## 8. 全画面（段階48）

Android の Chrome は、ページが下へスクロールされたと判断するとアドレスバーの帯を隠す（画面はスクロールしないが、読み込みの途中になぞった時などに隠れ、隠れると帯の中のメニューも出せない）。決まった形で全画面にする方法を2つ持つ。

- **ホーム画面のアイコンから開く**：`public/manifest.webmanifest`（`display: fullscreen`、`orientation: portrait`、`start_url` と `scope` は `./`）と、アイコン `public/icons/`（192・512、maskable の 512。タイトルの砂時計を夜の色の上に描いた絵。作り直しは `scripts/make_icons.mjs`）。`index.html` から読む。Service Worker は置かない（Chrome はなくてもホーム画面に置ける。オフラインで遊べるようにする時に考える）
- **ゲームの中のボタン**：`src/ui/fullscreen.ts`。`document.documentElement` を Fullscreen API で全画面にし（Android の下のバーも隠す `navigationUI: 'hide'`）、できる端末では縦向きに固定する。タイトルの左上のボタンと、オプションの窓の「全画面」の行。ボタンの押した後の処理（次のフレーム）でも、Chrome は押してから少しの間は全画面を許す
- 全画面にできないブラウザ（iPhone の Safari。`document.fullscreenEnabled` が false）と、ホーム画面のアイコンから開いた時（`display-mode: fullscreen` か `standalone` で、Fullscreen API の全画面ではない）は、ボタンも行も出さない
- 全画面になる・やめると画面の大きさが変わるが、Phaser の Scale FIT が合わせ直す

## 9. 確認を楽にする道具（段階92）

ゲームが長くなり、通しで遊んで確かめるのが難しくなったので、新しい所だけを本番に近い状態で確かめる道具を足した。

- **育ち具合で飛ぶ**（`src/sim/presets.ts`）：デバッグの「出来事へ飛ぶ」で、その出来事より前に通し終えた区画（`areasBefore`。晩に分けた区画は最後の晩の後から数える）を、自動対戦で出会う順に通して育ち具合を作る（星図・武器・ムーブメント・素材とポーチ・つながりゲージ。スナップは通した区画で手に入る物を足す。返した区画はその出来事より前の「返す」にそろえる。選んだ並びは空に戻す）
  - 手は弱点をねらう方針（`smart`）、星図は仲間ごとに順に、開けられる中で一番安い星から開く素直な伸ばし方（`StarPolicy` の `even`。でたらめな伸ばし方の偏りを入れない）
  - 段は3つ。**ふつう**：前もって30回通した中で、その区画の後の育ち具合（育ちを足した能力値の合計 `carryScore`）が真ん中の回。**控えめ**：下から1割の回。**やり込み**：ふつうの後に、最後に通した区画を2つ回り直したもの（狩りの代わり）
  - 前もって選んだシードは `src/sim/presetSeeds.ts`（`npm run presets` で作る。30回で約35秒）。区画や敵の数値を変えたら作り直す（作り直さなくても飛べるが、目安が少しずれる。区画を足した時はテストが止める）。飛ぶ時は1回だけ通す（PC で約1秒）。計算はデバッグで飛ぶ時だけ読み込む（`import()`）
  - 飛んだ後、画面の上に、段と通した区画の数、仲間ごとの武器のレベル・進化の回数・開けた星の数、星の砂の残りを8秒出す
  - 控えめとふつうの差は小さい（物語で戦う回数はみな同じなので、育ちの差は星図の伸ばし方と武器の素材の偏りくらい）。大きく差がつくのは、狩りをしたかどうか（やり込み）
- **飛ぶ前のセーブ**（`run.ts` の `backupBeforeJump`）：飛ぶ時に、今のセーブを `restopia.save.beforeJump` に取っておく。もう取ってある時は上書きしない（何度飛んでも、最初の本番のセーブに戻れる）。「飛ぶ前のセーブに戻す」で今のセーブに書き戻し、ページを開き直す（「つづきから」で続く）。「今の状態のまま続ける」で捨てる
- **その場のメモ**（`src/debug/memos.ts`・`memoPanel.ts`）：画面の左下の「メモ」から、どの画面でも書ける。種類（不具合・手応え・話・台詞・見た目・その他）を1つ選び、一言書く。開いた時の場所を自動で添える（何日目と出来事、会話の場面と台本の文字の何行目と台詞、戦闘の敵とラウンド、探索の区画と部屋、開いていた画面、版）。一覧の「全部写す」で、開発の会話に貼る文をクリップボードへ。1件ずつ・全部消せる。`restopia.memos` にセーブとは別に残す（「はじめから」や、飛んでも消えない）
