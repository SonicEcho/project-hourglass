# 設計書：昼の日常（屋台めぐり）と、小さな遊び

段階24・35・36。昼の日常（場所を選んで移り、印をタップして出来事を見る）と、プロローグの屋台めぐり、射的・金魚すくいの小さな遊び。数値の正は `src/data`。

## 1. 日常の形

- 物語の流れ（`docs/design/run.md` の 0.）の「昼の日常」の出来事ごとに、場所と印を `src/data/daily.ts` の `DAILY_HUBS` に書く（キーは出来事の id）。ロジックは `src/core/daily.ts`、画面は `src/scenes/DailyScene.ts`
- **場所**：名前、背景（会話の `BACKDROPS`）、地図の上の位置、印の一覧。場所が2つ以上なら、まず地図（「どこへ行く？」）を出し、場所をタップするとその場所の絵に移る。場所の絵には「地図へ戻る」
- **印**：名前（id）、見る会話の場面、印の種類、場所の絵の上の位置。種類は5つ

| 種類 | 印 | 中身 |
| --- | --- | --- |
| main | 赤の「！」 | 必ず見る出来事 |
| bond | 桃色の「♥」 | 絆の出来事 |
| talk | 青の「…」 | 小話 |
| stall | 橙の「★」 | 屋台（プロローグ） |
| go | 金の「→」 | ここへ行くと日が進む（夕暮れの時計屋）。選ぶ前に確かめる |
| hub | 紫の「扉」 | 時計屋の奥へ（レストピア）。レストピアの拠点の画面へ（段階50。`HUB_SPOT`。段階43の狩りの入口から替えた。返した区画があれば時計屋に出る。昼の回数を使わず、時間も進まない。地図の場所には添えない。`docs/design/economy.md` の 4.） |

- 印の状態：見られる（脈打つ）／見た（灰色に ✓。もう選べない）／まだ選べない（灰色。必ず見る出来事が残っている時の「→」と、先に見る印（`after`。段階36）をまだ見ていない印。タップすると「先に見ておきたい出来事がある：…」）
- 地図の場所には、まだ見ていない印（「→」を除く）を小さく添え、丸の下に印の言葉（必ず見る・絆・小話・屋台）を書く。場所の絵の印の上にも同じ言葉を書く（段階98）。地図の下に、必ず見る出来事が残っていればその名前と、「昼に選べるのはn回（♥絆と…小話）。！は数えない」（拠点の扉がある日は「！と扉は数えない」）、相手のいる小話がある日は「…小話は、その日に見た時だけ絆の帯が半分進む」を出す（段階125。レビューの項目48・49。後から拠点の「町の小話」で読んでも帯は進まないため）
- 地図の行き先の丸は半径 52（段階98。町の見下ろしの絵が届くまで、道だけの地図が空いて見えないように）
- 昼の日常を開いた時、その昼で一度だけ「保存しました（ここでやめても、この昼から始められる）」と出す（段階98）
- **見たかどうか**は、物語で覚えた値（`run.vars`）に「見た:印の id」として入れてセーブする（印を見終えて日常の画面に戻った時）。会話の場面がある印の id は、場面の id と同じにする
- **日常の終わり**：「→」の印を選んだ時、または「必ず見る出来事を全部見たら終わる」日常（屋台めぐり）で最後の1つを見た時に、物語の次の出来事へ進む
- 「誰と過ごすか」を選んで時間が進む仕組みは、段階35で作った（下の 4.）。回数を決めていない日常（2日目の昼）は、今までどおり何回でも見に行ける（1回見たら印は「見た」になる）

## 3. 小さな遊び（射的・金魚すくい）

- 台本に `@game 名前 成功の行き先 失敗の行き先` と書く（`docs/design/dialogue.md`）。会話の画面の上半分に遊びの画面を重ねて出し、終わったら結果の行き先へ進む。失敗しても話は進む（おまけをもらえる台詞がある）
- 判定は `src/core/minigame.ts`、数値は `src/data/minigames.ts`、画面は `src/scenes/miniGames.ts`

| 遊び | 遊び方 | 成功 | 失敗 |
| --- | --- | --- | --- |
| 射的（shooting） | 棚の上の景品（ブリキのロボットの形）が左右にゆれる。真ん中の円に来た瞬間にタップ。構えた時は右の端から（すぐ撃っても当たらない）。1発ごとに少し速くなる | 3発のうち1発当たる | 3発とも外れ |
| 金魚すくい（goldfish） | 水槽の金魚の1匹が、ときどき水面に近づいて光る。光っている間にタップ | 光っている間にタップ | 光っていない時に3回タップ（ポイが破れる）、または15秒たつ |

- 金魚が光る時間の並びは、周回のシードから決める（同じシードなら同じ並び）
- 7歳の遊びなので、やさしめにする：射的は真ん中を通る1回の間がおよそ0.12〜0.15秒（テストで 0.11秒以上を確かめる）
- 射的の景品と金魚の名前は、遊びの後の選択肢で選び、物語で覚えた値に入れる（1日目の朝、施設の台所に出てくる）

## 4. 誰と過ごすか（段階35）

- **昼に選べる回数**：日常のデータの `picks`（M2 は2回。`DAILY_PICKS`）。絆の出来事（♥）と小話（…）を1つ見るごとに1回使う。必ず見る出来事（！）と「→」は使わない。題の下に「昼に選べるのは、あと○回」
- **使い切ると夕暮れ**：回数を使い切り、必ず見る出来事も全部見たら、印を見終えた所で物語の次の出来事へ進む。使い切った後の絆と小話の印は灰色で、タップすると「今日は、もう時間がない」（状態 `spent`）
- **絆の出来事**：`src/data/daily.ts` の `BOND_EVENTS` に、相手ごとに順番に並べる（id は会話の場面の id、題、印の名前、何日目から、場所、位置）。日常のデータの `partners` に書いた相手ごとに、まだ見ていない一番前の出来事の印を、その出来事の場所に出す（`resolveHub`）。「何日目から」より前なら出さない（飛ばして先の出来事を出さない）。見なかった出来事は、次の日も同じ所から
- **同じ相手は1日に1回**：見た相手は「会った:日常の id:相手」に、見た出来事の id を覚える。その日は、その出来事の印が「見た」のまま残り、続きは次の日に出る
- **絆の深さ**：相手の、見た絆の出来事の数（`bondLevel`）。段階83から、その日に見た小話も半分の♥として数える（`bondPoints`。4-2）。地図の下に、相手ごとの「Lv」（絆の出来事の数）と、次の Lv までの短い帯（その日に見た小話の半分）を出す（段階110。テストプレイのメモ 29：前は「あかり ♥♥♡」のように♥を並べていて、増えると見づらかった。`bondGauge`）。見たかどうかは今までどおり `run.vars` に入るので、セーブの形は変えない
- **町の地図**：場所の位置は `TOWN` に1つずつ書き、どの日も同じ位置に出す（列 x＝85・195・305、行 y＝200・330・460・590）。地図には格子の道を描く。日常のデータは `TOWN` の場所に印を置いて書く。絆の出来事の場所が、その日の日常にない時は、`TOWN` から足す（「→」のある場所より前）。印のない場所は出さない

| 相手 | 絆の出来事（何日目から） |
| --- | --- |
| あかり | 1「シャッター、ハルトが言って」（1日目・屋上）、2「消せない写真」（3日目・屋上）、3「りくのいない帰り道」（4日目・川沿いの道）、4「最初の五分」（5日目・施設） |
| みお | 1「助っ人のみお」（6日目・河川敷）、2「あとで一緒に食べよう」（7日目・コンビニ） |

M2 の昼（3日目〜8日目）の印は `docs/milestones/M2.md` の段階35の詳細。会える相手は、1章と5日目はあかり、6日目からはあかりとみお。

### 4-2. 選ぶ意味を持たせる（2026-10-20 開発者と決めた。案A）

それまでは、どの日も選べる話（絆の出来事と小話）が2つ以下で、「1日2回まで」の制限が一度も効いていなかった（開発者の指摘）。昼は「限られた時間を誰と過ごすか」を選ぶ場面にする。

- **1日に並ぶ話は3〜4つ、選べるのは2つ**（`DAILY_PICKS` は2のまま）。必ず見る出来事は、今までどおり数に入らない
- **絆の出来事は次の日に繰り越す**（今のまま）。だれの話も、いつかは最後まで見られる
- **小話はその日だけ**。全部は見られない。遊ぶたびに見る話が少し変わる。小話は短く軽い話にして、物語の大事なことは入れない（見逃しても話が分かる）
- **絆の深さ（♥）は戦闘に効かせない**（開発者の考え：戦闘に効く要素はもう多い）。物語の側に効かせる：
  1. 絆の出来事の会話の中身：前の出来事で選んだ一言や、♥の数で、台詞が少し変わる
  2. 物語の場面の一言：章の山場の後などで、♥が一番多い仲間が声をかける（その場面の1〜2行だけ変わる。話は分けない）
  3. 章の終わりの夕暮れ：♥が一番多い相手との、短い場面が付く
- 台本に「♥の数で台詞を変える」書き方が要る（今の台本は、選んだ値 `@set` の差し替えしかない）。仕組みは、使う台本を書く段階で作る
- 作る順番：2章の作り直しで、日ごとの小話を足して並べ直す（2-2 の脚本から。2-1 の日（9・10・12日目）にも足す）
- **見逃した小話は、後から拠点で見られる**（段階82。開発者の考え：周回して遊ぶ前提ではないので、取りこぼしをなくす）。拠点（レストピア）の「町の小話」に、過ぎた日の小話を日の順に並べる。見なかった小話には「まだ」の印。見た小話も見直せる。日も昼の回数も使わない。昼に選ぶのは「その日に見るか、後で見るか」になる（その日に見ると、昼の流れの中で読める）
- **小話は、その日に見た時だけ♥に数える**（段階83。開発者の考え：後から自由に見られると、2つ選ぶ意味が薄まる）。小話ごとに「誰との話か」（`DailySpot` の `with`。話の中心の仲間を1人。どちらとも言えない話は書かない）を決め、昼に見た時だけ、その仲間の♥を半分足す（絆の出来事は1つで2点、小話は1点。`BOND_POINTS`）。「町の小話」で後から見た時は、見たことを別の値（`記録:印の id`）で覚え、♥は増えない。地図の印の名前に相手を出す（「台所（小話・あかり）」）。昼に選ぶのは「今日は誰と過ごすか」になり、取りこぼしはないが、待っても♥は得られない
- **♥で台詞を変える台本の書き方**（段階82）：`@if 名前 値 行き先`（覚えた値が合えば行き先の印へ飛ぶ）。会話の始めに、♥が一番多い仲間の名前を `絆の一番` という値で渡す（同じ数なら、絆の出来事の並びの先の相手。今は、あかり。段階83から、小話の♥も含めて比べる）

## 5. 返した翌日に持ち主に会う（段階36）

- **データ**：`src/data/daily.ts` の `RETURN_VISITS` に、区画ごとに1つ（区画の id、会話の場面の id、印の名前、町の地図の場所、位置）。日ごとの日常のデータには書かない
- **出る日**：区画の時間を返した次の日の昼（日常のデータの `day` が、返した日＋1）。必ず見る出来事（赤の「！」）として、その場所の印の先頭に出る。場所がその日の日常になければ、`TOWN` から足す（絆の出来事と同じ。`resolveHub`）
- **返した日**：物語の流れの「時間を返す」出来事のうち、今の出来事より前にあるもの（`src/core/flow.ts` の `returnDays`）。中身のある返す出来事は、返した記録（セーブの `returned`）にある区画だけ。仮の画面の返す出来事は、通ったら返したことにする。返した日は流れから決まるので、セーブには足さない
- **ごほうびのギア**（段階39）：`RETURN_VISITS` に `gears` を書くと、その出来事を見終えた時にギアが手に入る（「ギアを手に入れた！」。同じ出来事で2回はもらえない。`spotGears`）。2-1 の翌日に、いさむが最後に削った歯車をくれる（脚本の「返した報酬のギア」）
- **1日に必ず見る出来事が2つある日**：後の印に先に見る印（`after`）を書く。先の印がその日に出ていて、まだ見ていなければ「まだ選べない」（6日目は工場の後に楽器店、7日目は楽器店の後にパン屋）

| 区画 | 翌日 | 場所と印 |
| --- | --- | --- |
| 1-1 | 2日目 | 商店街：コンビニの前（ゆうま） |
| 1-2 | 4日目 | 時計屋：来る日じゃないのに（ふみ） |
| 2-1 | 6日目 | 工場：いさむの工場（6-A。段階39。見終えると、ごほうびのギア「バトンレシーバー」） |
| 2-2 | 7日目 | 楽器店：閉店後の楽器店（けんたたち） |
