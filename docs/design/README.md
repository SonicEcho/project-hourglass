# 設計書の一覧と、文書の決まり

段階14（2026-10-07）で、試作の仕様書（`docs/SPEC.md`）を、今の仕組みを書いた「設計書」と、作業の一覧に分けた。

## 文書の役割

| 文書 | 役割 | 書き換えるか |
| --- | --- | --- |
| `docs/design/battle.md` | 戦闘のルール | 今の仕組みに合わせて上書きする |
| `docs/design/growth.md` | 育成（星図・ムーブメント・武器） | 同上 |
| `docs/design/run.md` | 周回・画面の移り変わり・セーブ | 同上 |
| `docs/design/tech.md` | 技術・テスト・自動対戦の測定・デバッグ・公開 | 同上 |
| `docs/milestones/M0.md` など | マイルストーンごとの作業の一覧（段階ごとの依頼内容と、スマホで確かめること）、完成の基準 | 段階を足す・進み具合を書く |
| `docs/ROADMAP.md` | マイルストーン全体の道のり | 方針が変わった時 |
| `docs/CONCEPT.md` | ゲーム全体の構想ノート（背景）。ここにあって設計書にない要素は、まだ作らない | 構想が変わった時 |
| `docs/STORY.md`・`docs/NAMING.md` | 物語、名前と用語 | 決まった時 |
| `docs/HANDOFF.md` | 新しいセッションへの引き継ぎメモ（最初に読む） | 作業のたび |
| `docs/SPEC.md` | 試作（段階1〜14）の記録。段階ごとの経緯と、当時の決定 | 書き足さない |

探索・物語・修復などの設計書は、その仕組みを作る時（M1 以降）に足す。

## 書き方の決まり

- **設計書には「今の仕組み」だけを書く**。仕組みを変えたら本文を上書きし、なぜ変えたかは、その設計書の最後の「決定の記録」に、日付・段階・理由を1〜2行で残す
- **数値の正は `src/data`**。設計書には、ルールに関わる数値（手札5枚、弱点1.5倍など）と目安（勝率など）だけを書き、キャラ・スナップ・敵ごとの細かい数値の表は写さない（二重に書くと食い違うため）。代わりに、どのファイルにあるかを書く
- **用語とキャラ名は `docs/NAMING.md`・`docs/CONCEPT.md` に合わせる**（ハルト、星図、星の砂、ムーブメント、ブリッジ、狂い、ギア、スナップ、アルバム、延長、記憶の欠片、時分解）。コードの識別子は古いまま（`navi`、`card`、`fragment`、`oneMore` など）で、対応は `docs/SPEC.md` の段階10の表
- **段階の番号は続けて使う**。段階は、そのマイルストーンの文書に「依頼する内容」と「スマホで確かめること」を書いてから作る
- 仕様と違う判断をした時や、書かれていないことを決めた時は、関係する設計書に書き足す
